로직 · 조사 범위

  2. 이미 읽은 Batch Report는 다시 읽지 않기(기본 켜짐): 파일 이름 · 수정시각 · 크기가 지난 조사 때와 같으면 로컬 캐시(배치분석/누적)의 내용을 그대로 쓰고, 새로 생기거나 바뀐 것만 엽니다. 끄면 고른 범위를 전부 다시 엽니다(캐시가 의심될 때 · 판정 규칙이 바뀐 직후).
  3. 읽은 Batch Report를 Lot 단위로 모아 Lot 추적 · 가동률 · WPH가 같은 결과를 씁니다. 기간은 스캔 시작일 기준입니다.
  4. 호기 사이에는 2초 간격으로 순서대로 읽습니다(장비 접속 매너). 연결이 안 되는 호기는 캐시만으로 보여 주고 표시합니다.
LOT 추적

Lot 추적이란?

왜 필요한가요?

Batch Report 1장은 스캔 1번입니다. 한 Lot은 Error로 다시 스캔하거나, 웨이퍼를 나눠 스캔하거나, 다른 호기로 옮겨 스캔하면 Batch Report 여러 장에 흩어집니다.

무엇을 보여 주나요?

조사 범위의 Batch Report를 Lot 단위로 다시 모아 언제 · 어느 호기에서 · 몇 번 스캔했는지, 어떤 wafer가 어떤 Error로 다시 스캔됐는지, 결국 모든 wafer가 Pass했는지 보여 줍니다.

이렇게 쓰세요

Lot 단위 Scan List

로직 · Lot 추적
  1. Batch Report 1장 = 스캔 1번. S/M 안 첫 영문 3글자 = Lot 코드이고, 전체 Wafer ID(앞 5자)가 있으면 Lot ID로 다시 확인합니다.
  2. 같은 Lot을 같은 호기에서 12시간 이내로 다시 스캔하면 이어서 스캔한 것(재스캔 · 나눠 스캔)입니다. 다른 호기는 48시간 이내 + 앞 스캔에 Pass하지 못한 wafer + 같은 공정 단계(Recipe(s))일 때만 이어서 호기 이동으로 표시합니다.
  3. 공정 단계가 바뀌면(예: 2D_WBG → 2D) 같은 Lot 안에서 줄을 나눠 셉니다 — 같은 wafer를 두 번 더하지 않기 위해서입니다.
  4. wafer 결과: 한 번에 Pass · 재스캔 Pass · 중복 Pass · Pass 없음. 같은 wafer가 2번 이상 Pass면 가장 나중 Pass를 씁니다(추천 · 기본). 직접 바꾸고 저장하는 것은 개발자 기능입니다.

호기 가동률과 낮은 이유

로직 · 가동률
  1. 달력 시간(호기마다 하루 24시간) = 유효 스캔 + Error·중복 스캔 + 재스캔 전 대기 + 점검 스캔 + 기타.
  2. Batch Report 1장의 Batch Time을 Dice가 있는 wafer 행 수로 똑같이 나눠 wafer 1장 몫을 구합니다. 최종 결과로 쓰는 wafer 몫 = 유효 스캔, Error가 난 wafer 몫과 이미 Pass한 wafer를 다시 스캔한 몫 = Error·중복 스캔입니다. Dice 있는 행이 없으면(예: 전부 Nothing to Scan.) Batch Time 전부를 Error 행 비율로 나눕니다.
  3. Error 원문별 시간: 한 Batch Report에 Error가 여러 종류 섞여 있어도 wafer마다 자기 Error 원문(첫 문구)으로 따로 셉니다. 앞 Error 뒤 따라온 Aborted · Skipped(연쇄)는 그 앞 Error 원문으로 셉니다. 예) Batch Time 50분 · Dice 있는 25행 · Scan 2D Error. 3장 · 연쇄 Aborted. 2장 → wafer 1장 몫 2분, Scan 2D Error.에 10분(5장), 유효 스캔 40분.
  4. 재스캔 전 대기 = Error 뒤 같은 Lot을 다시 스캔하기까지 걸린 시간 중 장비가 아무것도 스캔하지 않은 시간(그 사이 다른 Lot을 스캔했으면 뺌). 앞 Batch Report의 Error wafer 원문 비율로 나눠 셉니다.
  5. 기타 = 나머지(대기 · PM · 셋업 · 전원 OFF — Batch Report로 구분 불가). 프로토타입은 스캔 시작일로 나누고, 실제 구현은 자정을 넘긴 시간을 날마다 나눠 넣습니다.

※ 보내주신 자료는 거의 Job 하나(CMP2D-DT-GH10N…)의 Batch Report라 다른 레시피를 스캔한 시간이 빠져 가동률이 낮게 나옵니다. 예시 호기(AOI-1~29)는 자료가 없어 전부 기타로 잡힙니다.

WPH

호기 · 레시피별 처리량 (Wafers Per Hour)

정상 스캔 WPH

Lot을 한 번에 25매 모두 Pass한 Batch Report만으로 잰 속도. 장비가 막힘없이 돌 때 1시간에 몇 매를 스캔하는지.

Σ25매 × 3600 ÷ ΣBatch Time
실제 WPH (재스캔 포함)

Lot마다 최종 Pass한 wafer 수를 그 Lot에 쓴 모든 Batch Time(Error · 재스캔 · 나눠 스캔 포함)으로 나눈 속도.

ΣPass wafer × 3600 ÷ Σ(Lot에 쓴 모든 Batch Time)

Batch Report 찾기 · Lot 취합

    호기 범위
    로직 · 검색
    1. 고른 호기 Reports 폴더의 파일 이름만 봅니다(원본을 열지 않아 빠름). 키워드는 대소문자 무시, 여러 단어는 모두 포함, 기간은 파일 이름 안 날짜.
    2. 찾은 Batch Report를 Lot · 공정 단계로 모아 보여 줍니다. 같은 Lot을 이어서 스캔했는데 키워드에 안 걸린 Batch Report(S/M 꼬리가 다른 것 등)도 회색으로 함께 보여 놓칠 일이 없게 합니다.
    로직 · 고르기
    1. 원문 보기 = 캐시에 읽어 둔 Batch Report의 표를 그대로 앱 안에서 보여 줍니다. 원본 열기 = 장비 Report 폴더의 .htm을 기본 브라우저로 엽니다(읽기 전용).
    2. Scanresult 경로 = 같은 호기 루트의 Scanresult*(백업 포함) \Job\Setup\S/M. 실제 앱은 폴더 이름만 확인해 있는 곳을 보여 줍니다.
    3. 여러 Lot을 함께 골라도 됩니다. 취합은 Lot · 공정 단계마다 따로 합니다(WBG · CMP처럼 다른 공정 스캔을 더하지 않음).
    선택 0개
    로직 · 취합
    1. 고른 Batch Report를 Lot · 공정 단계별로 모으고, wafer는 슬롯(25행이면 1행=25번, 아니면 Wafer ID)으로 맞춥니다.
    2. 같은 wafer가 2장 이상에 있으면 최신 스캔으로 자동 취합합니다(Pass가 있으면 가장 나중 Pass, 없으면 가장 나중 스캔). 직접 고르는 창은 개발자 기능에서만 나옵니다. 쓴 행 하나만 Scanned · Bad · Good을 더합니다.
    3. 결과 화면의 원문 보기로 고른 Batch Report와 wafer 행마다 쓴 Batch Report 원문을 바로 엽니다.
    4. Excel에는 Lot 취합 시트와 wafer 시트(쓴 Batch Report 이름 · 원문 포함)를 씁니다(로컬 결과 폴더).
