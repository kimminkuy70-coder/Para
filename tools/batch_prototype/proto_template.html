어느 호기의 어느 기간을 볼까요?

호기

조사를 시작하면 고른 호기의 Report 폴더에서 새로 생긴·바뀐 Batch Report만 읽고, 나머지는 로컬 캐시를 씁니다.

로직 · 조사 범위
  1. 고른 호기의 Reports 폴더(추가 백업 폴더 포함)를 읽기만 합니다. 파일 이름과 수정시각·크기로 새로 생긴·바뀐 Batch Report만 다시 읽고, 나머지는 로컬 캐시(배치분석/누적)를 씁니다.
  2. 읽은 Batch Report를 시도 → 묶음 → Lot으로 한 번에 묶어 ① ③ ④가 같은 결과를 씁니다. 기간은 시도 시작일 기준입니다.
  3. 호기 사이에는 2초 간격으로 순서대로 읽습니다(장비 접속 매너). 연결이 안 되는 호기는 캐시만으로 보여 주고 표시합니다.
① LOT 추적

Lot 단위 스캔 이력

로직 · Lot 추적
  1. Batch Report 1장 = 스캔 시도 1번. S/M 안의 영문 3글자 = Lot 코드, 전체 Wafer ID(앞 5자)가 있으면 Lot ID로 다시 확인합니다.
  2. 같은 호기에서 12시간 이내로 이어진 시도 = 묶음(한 번의 검사). 다른 호기는 48시간 이내 + 앞 묶음에 Pass 못 한 웨이퍼 + 같은 공정 단계(Recipe(s))일 때만 이어 호기 이동으로 표시합니다.
  3. 묶음 안에서 웨이퍼(슬롯)마다 결과: 한 번에 Pass · 재스캔 Pass · 중복 Pass · Pass 없음. 중복 Pass는 가장 나중 Pass를 추천하고, 사람이 바꾸면 로컬에 저장해 ② ③ ④도 같은 선택을 씁니다.
  4. Lot을 누르면 Lot 취합 → 웨이퍼 취합이 먼저, 그 아래 시도 이력과 오류 지도가 나옵니다. 오류는 원문 그대로입니다.

② 찾기 · 취합

Batch Report 찾기 · Lot 취합

    호기 범위
    로직 · 검색
    1. 고른 호기 Reports 폴더의 파일 이름만 봅니다(원본을 열지 않아 빠름). 키워드는 대소문자 무시, 여러 단어는 모두 포함, 기간은 파일 이름 안 날짜.
    2. 찾은 Batch Report를 Lot · 묶음으로 묶어 보여 줍니다. 같은 묶음인데 키워드에 안 걸린 Batch Report(S/M 꼬리가 다른 것 등)도 회색으로 함께 보여 놓칠 일이 없게 합니다.
    로직 · 고르기
    1. 원문 보기 = 캐시에 읽어 둔 Batch Report의 표를 그대로 앱 안에서 보여 줍니다. 원본 열기 = 장비 Report 폴더의 .htm을 기본 브라우저로 엽니다(읽기 전용).
    2. Scanresult 경로 = 같은 호기 루트의 Scanresult*(백업 포함) \Job\Setup\S/M. 실제 앱은 폴더 이름만 확인해 있는 곳을 보여 줍니다.
    3. 여러 Lot·묶음을 함께 골라도 됩니다. 취합은 Lot · 묶음마다 따로 합니다(WBG·CMP처럼 다른 검사를 더하지 않음).
    선택 0개
    로직 · 취합
    1. 고른 Batch Report를 Lot · 묶음별로 모으고, 웨이퍼는 슬롯(25행이면 1행=25번, 아니면 Wafer ID)으로 맞춥니다.
    2. 같은 웨이퍼가 2장 이상에 있으면 알림 창에서 고릅니다. 추천 = 가장 나중 Pass(없으면 가장 나중 스캔). 고른 행 하나만 Scanned · Bad · Good을 더합니다.
    3. Excel에는 Lot 취합 시트와 웨이퍼 시트(고른 Batch Report 이름·원문 포함)를 씁니다(로컬 결과 폴더).

    ③ 가동률 · 원인

    호기 가동률과 낮은 이유

    로직 · 가동률
    1. 달력 시간 = 유효 스캔 + 버려진 스캔 + 재스캔 대기 + 점검 스캔 + 기타.
    2. 시도의 Batch Time을 Dice가 있는 웨이퍼 행 수로 나눠 웨이퍼 1장 몫을 구합니다. 최종으로 고른 웨이퍼 몫 = 유효 스캔, 나머지 = 버려진 스캔(그 웨이퍼의 오류 원문으로 집계, Pass를 다시 스캔한 것은 'Pass 다시 스캔(중복)'). Dice 있는 행이 하나도 없으면 Batch Time 전부가 버려진 스캔입니다.
    3. 재스캔 대기 = 같은 묶음에서 앞 시도 끝 → 다음 시도 시작 사이 중 장비가 아무것도 스캔하지 않은 시간만(그 사이 다른 Lot을 스캔했으면 빼고), 앞 시도의 첫 오류 원문으로 집계.
    4. 기타 = 나머지 시간(대기 · PM · 셋업 · 전원 OFF는 Batch Report로 구분할 수 없음).
    5. 프로토타입은 시도 시작일로 나눕니다. 실제 구현은 자정을 넘긴 시간을 날마다 나눠 넣습니다(현재 M02 방식).

    ※ 보내주신 자료는 거의 Job 하나(CMP2D-DT-GH10N…)의 Batch Report라서 다른 레시피를 스캔한 시간이 빠져 가동률이 낮게 나옵니다. 실제로는 호기의 Reports 폴더 전체를 조사합니다.

    ④ WPH

    호기 · 레시피별 처리량

    로직 · WPH
    1. 레시피 = Batch Report 안의 Job · Recipe(s)(공정 단계). 장비 Job 폴더는 필요할 때 폴더 이름 목록만 읽어 호기별 레시피를 맞춥니다(파일은 열지 않음).
    2. 기준 WPH = 25행이 모두 Pass인 Batch Report만: Σ웨이퍼 × 3600 ÷ ΣBatch Time (장비가 막힘없이 돌 때).
    3. 실효 WPH = 묶음 단위: Pass 웨이퍼 수 × 3600 ÷ 그 묶음의 모든 시도 Batch Time 합(나눠 스캔·재스캔·실패 시간 포함).
    4. 손실률 = 1 − 실효 ÷ 기준. 같은 레시피를 호기끼리 나란히 비교합니다.
