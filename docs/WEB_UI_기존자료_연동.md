# 기존 프로그램(tkinter) 자료를 웹 UI에서 쓰기

**결론: 변환 작업은 없습니다.** 웹 UI는 기존 프로그램과 **같은 설정 파일, 같은 저장폴더, 같은 파일 형식**을 그대로 읽고 씁니다.
아래 3가지만 맞으면 기존에 만든 양식·취합·문서·조사 결과가 그대로 보입니다.

1. 같은 **설정 파일**을 쓰거나(같은 PC·같은 계정), 새 PC라면 같은 저장폴더를 지정한다.
2. **로컬 작업 폴더**를 기존 프로그램이 쓰던 곳과 같게 둔다(Commonality·배치 결과가 거기 있음).
3. 두 프로그램을 **동시에 켜지 않는다**.

---

## 1. 같은 PC에서 기존 프로그램을 쓰던 경우

설정은 `%USERPROFILE%\.pi_param_manager.json` 하나를 두 프로그램이 같이 씁니다. 웹 앱을 켜면 다음이 **자동으로** 이어집니다.

| 설정 키 | 내용 | 웹 UI 에서 보이는 곳 |
|---|---|---|
| `save_dir` | 저장폴더 | 설정 › 저장폴더 |
| `local_dir` | 로컬 작업 폴더 | 설정 › 로컬 작업 폴더 |
| `wph_report_paths` / `batch_extra_paths` | 호기별 Report 폴더 / 추가 폴더 | 설정 › 배치 Report 폴더 · 배치 자동·추가 폴더 |
| `commonality_roots` | 호기별 Scanresult 루트 | 설정 › Scanresult 루트 |
| `batch_auto` / `batch_schedule` | 배치 하루 1회 자동 갱신, 마지막 실행 시각 | 설정 › 배치 자동·추가 폴더 |
| `local_root` | 값 업데이트용 '로컬 상위 폴더' | 값 업데이트 › 로컬 복사본 |
| `hide_kla` | KLA 장비 숨기기 | Recipe 관리 |

확인만 하면 됩니다: 웹 앱 **[설정]** 각 탭에 기존 경로가 보이면 연동된 것입니다.

> `batch_schedule` 을 같이 쓰므로 두 프로그램이 같은 날 배치 자동 갱신을 두 번 하지 않습니다.

## 2. 다른 PC(또는 다른 사람)가 웹 UI만 쓰는 경우

설정 파일은 PC·계정마다 따로입니다. 그 PC에서 [초기 설정](WEB_UI_초기설정.md) 3장을 하되:

- **저장폴더 = 팀이 이미 쓰는 OneDrive 폴더** 를 지정합니다. 공유 자료는 모두 여기 있으므로 이것만으로 대부분 연동됩니다.
- Report 폴더·Scanresult 루트·로컬 상위 폴더는 **PC마다 경로가 다를 수 있어** 각자 등록합니다(드라이브 문자 등).
- 로컬 작업 폴더의 결과(Commonality·배치 분석)는 **그 PC 것만** 보입니다(공유 대상이 아님 — 아래 4장).

## 3. 저장폴더(OneDrive) — 공유 자료, 그대로 읽고 씀

| 기존 파일/폴더 | 웹 UI | 비고 |
|---|---|---|
| `장비 IP 주소.xlsx` | [장비 IP] 조회·편집, 값 업데이트·양식 확정의 호기 목록 | 편집 잠금(`.editlock`)을 서로 존중. 숨겨진 옛 '접속ID' 열은 보여 주거나 복제하지 않음 |
| `특이사항.xlsx` / `참고자료.xlsx` | [특이사항]/[참고자료] | 셀 색 유지. '종료 여부' ☑/☐ 형식 동일 |
| `변환계수.xlsx` | 값 업데이트·Commonality 계산에 조회, 양식 확정 때만 기록 | 규칙 동일(읽는 작업은 파일을 고치지 않음) |
| `장비화면이름.xlsx` | 양식 편집기에서 이름·체크 자동 채움, 양식 확정 때 기록 | 동일 |
| `양식\{레시피}\{시각}\…` | [양식 만들기](원본 편집·새로 만들기), 값 업데이트 기준 양식 | 회차 폴더·`관련파일\_원본_` 구조 동일 |
| `파라미터 값 취합\파라미터 값 취합_{시각}.xlsx` | [Recipe 관리]가 최신 것을 표시, [이력 확인] 비교 대상 | 웹의 값 업데이트도 같은 이름으로 새 파일을 만듦 |
| `값확인_셀색상.json` | [Recipe 관리] 셀 색칠 | 기존 값 확인 화면의 칸 색과 같은 파일 |
| `감시설정.json` | 값 업데이트 때 확정한 Job 폴더 계획 저장, 레시피 삭제 때 정리 | 자동 감시 자체는 아직 기존 프로그램 기능 |
| 저장폴더 옆 `프로그램\` | 웹 게시본 `…_web_v*.zip` + `버전정보_web.json` 추가 | 기존 exe·`버전정보.json` 은 건드리지 않음 |

## 4. 로컬 작업 폴더 — 이 PC의 결과

웹 UI는 `local_dir`(설정 › 로컬 작업 폴더) 아래에서 다음을 찾습니다. **기존 프로그램과 같은 폴더를 지정해야** 예전 결과가 보입니다.

| 위치(로컬 작업 폴더 기준) | 내용 | 웹 UI |
|---|---|---|
| `Commonality\commonality\{호기}\{시각}\조사_*.xlsx` | 수동 Commonality 조사 결과 | Commonality › 저장 결과 비교 목록 |
| `commonality\자동감시\{호기}\결과\감시조사_*.xlsx` | 자동 감시 조사 결과 | 같은 목록 |
| `배치분석\…`, `Cache\` | 배치 리포트 분석 결과·증분 캐시 | 배치 리포트 분석(캐시를 이어서 씀) |
| `Logs\` | 오류 로그 | 설정 › 정보 › 오류 로그 폴더 |
| `삭제보관\` | 삭제한 레시피 양식(되돌리기용) | 레시피 삭제 시 여기에 보관 |

**예전 결과가 안 보일 때**
1. 기존 프로그램 ⋯파일 > 로컬 작업 폴더(또는 설정 파일의 `local_dir`)에서 경로를 확인합니다.
2. 웹 UI [설정 › 로컬 작업 폴더]에서 **그 폴더의 상위 폴더**를 고릅니다(끝에 `CamtekAOI` 가 자동으로 붙습니다. 이미 `…\CamtekAOI` 를 고르면 그대로 씁니다).
3. 기존 로컬 폴더가 **프로그램 exe 옆**이었다면 그대로 써도 되지만, 앞으로는 웹 앱 설치 폴더 **안**으로는 지정할 수 없습니다(업데이트 때 설치 폴더가 교체됨).

설정에 `local_dir` 이 전혀 없으면 웹 앱은 `%LOCALAPPDATA%\CamtekAOI` 를 씁니다. 이때는 예전 결과가 다른 곳에 있으니 위 1~2를 해 주세요.

## 5. 이어지지 않는 것 / 주의

| 항목 | 설명 | 대응 |
|---|---|---|
| **동시 실행** | 두 프로그램이 같은 단일 실행 잠금을 씀 | 한 번에 하나만. 기존 프로그램(트레이 포함)을 끄고 웹 앱 [다시 연결] |
| **자동 감시·트레이** | 파라미터/Commonality 자동 감시는 아직 기존 프로그램 기능 | 감시가 필요한 PC는 기존 프로그램 유지 |
| **접속자 표시** | 웹 UI 사용자는 기존 프로그램의 '👥 현재 접속' 목록에 나오지 않음 | 문서 편집 잠금은 서로 존중하므로 동시 편집 충돌은 막힘 |
| **배치 '마지막 조사 조건'** | 웹은 로컬 `Cache\rev1_batch_last.json` 에 따로 저장(없으면 기존 조건을 읽음) | 기존 프로그램의 조건을 덮어쓰지 않음 |
| **WPH 조사 화면** | 웹은 배치 리포트 분석(10지표)으로 대체 | 기존 `WPH조사\` 결과 폴더는 그대로 남음 |

## 6. 권장 전환 순서

1. 한 PC에서 기존 프로그램을 **종료**하고 웹 앱을 설치·실행([초기 설정](WEB_UI_초기설정.md)).
2. [설정] 각 탭에 기존 경로가 보이는지, [Recipe 관리]에 최신 취합이 뜨는지 확인.
3. [Commonality › 저장 결과 비교]에 예전 결과가 보이는지 확인(안 보이면 4장).
4. 값 업데이트·양식 만들기 등 **쓰기 작업은 한 번 시험**한 뒤 팀에 알립니다(파일 형식이 같아 기존 프로그램에서도 그대로 열림).
5. 자동 감시를 쓰는 PC는 당분간 기존 프로그램을 유지합니다.
