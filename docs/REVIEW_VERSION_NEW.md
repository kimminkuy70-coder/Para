# version_new 검토 및 변경 기록

기준: version_v7.0의 ad895aedf298637df548b3963f30bf700ed79f14에서 분기.
작업 범위는 version_new만. 원본·다른 브랜치와 실제 OneDrive 게시물은 수정하지 않는다.

## 검토 범위와 한계

패키지 34개 Python 모듈의 구문·구조 및 외부 통신/프로세스 호출 위치를 확인했다.
장비 수집, 파일 저장·잠금, 감시, 업데이트, WPH, GUI 작업 처리 경로를 집중 검토했다.
기존 파서·양식·취합·이력·참고자료 등은 기존 독립 테스트로 회귀를 확인한다.
전체 화면을 실제 조작하거나 모든 경로의 결함 부재를 증명한 것은 아니다.
이 환경에서는 Windows GUI, 실제 장비망, OneDrive 다중 PC 동기화,
Excel 수식 계산 및 exe 빌드·교체를 실행하지 못한다.

| 설정 | 잘못된 최상위 JSON 방어, 로컬 사용자 설정만 임시 작성 후 교체 | 교체 실패 시 기존 설정 및 임시 정리 검사. 공유 설정은 임시파일 추가 없이 직렬화 후 저장 |

| Windows 실행 | HANDLE 인자 형식 지정, 이전 프로그램 제목으로 기존 창 탐색 | 64비트 실기와 구·신버전 동시 실행 시도 필요 |
| 환경 | build/run_dev가 requirements 파일을 사용 | 런타임 추가 의존성 없음. Python/Windows 빌드 환경 자체를 새로 설치하지 않음 |
| 보안·OneDrive | 로그 실패 시 공유 폴더 fallback 제거, 공유 JSON 임시파일 추가안 철회 | 로그 fallback이 공유 폴더를 쓰지 않는 테스트 추가. 기존 장비/OneDrive 보안 회귀 유지 |
| 협업 | AGENTS/ai_sync/협업 안내를 version_new로 변경 | 다른 브랜치로 push하지 않음. 대화 내용 자체는 AI 간 공유되지 않음 |

## 유지한 보안·OneDrive 제약

- 장비 파일 읽기 전용, 기존 탐색기 세션만 사용. net use 인증·ID/비밀번호 저장 재도입 없음.
- 런타임 인터넷 호출·GitHub 폴링 없음. 개발 시 GitHub 소스 반영과 프로그램 배포를 구분.
- openpyxl/tksheet 외 런타임 의존성 추가 없음. conda 사용 없음.
- 장비 순차 접근과 장비·파일 사이 간격, 감시 backoff, 세션 300초 갱신 규칙 유지.
- 원본 수집물·WPH/Commonality 결과·캐시·로그는 기존 localdirs 경로 사용.
- 공유 JSON은 새 임시파일을 추가하지 않는다. 기존 exe 게시의 .tmp 방식은 유지한다.
  공유 JSON 저장은 원자적 트랜잭션이 아니다. 동기화 도중 읽은 manifest는 실패 처리 후
  다음 확인에서 재시도하며, exe는 크기·SHA-256 검증을 통과해야 적용한다.
- OneDrive 파일 잠금은 소프트 락이다. 로컬 atomic replace도 여러 PC 사이의
  원자성·즉시 전파를 제공하지 않는다. 기존 저장 직전 변경 검사·충돌본 탐지를 유지한다.
- 배포 담당자는 한 명으로 운영하고, 동기화 완료 전 다른 PC의 업데이트를 진행하지 않는다.
  manifest와 exe가 다른 순서로 도착할 수 있으므로 검증 실패 시 동기화 완료 후 재시도한다.
- SHA-256은 내용 일치 검사이며 게시자 인증이 아니다. 공유 배포 폴더 쓰기 권한은
  기존 조직 권한으로 관리해야 한다. 프로그램은 권한·백신 설정을 변경하지 않는다.

## 배포 호환성

| 대상 | 처리 |
|---|---|
| 기존 사용자 설정 | ~/.pi_param_manager.json 경로·키 유지 |
| 기존 공유 Excel/감시설정/잠금 | 파일 구조·키·식별자 변경 없음; 강제 마이그레이션 없음 |
| 이전 exe 이름 | PI_Param_Manager.exe 및 Camtek_AOI_Parameter_manage_v* 인식 유지 |
| 새 exe 이름 | Camtek_AOI_manager_v<입력 버전>.exe |
| 버전 번호 | 소스 기본값 8.0 유지. 실제 새 배포는 설치본보다 높은 번호(예: build.bat 8.1)로 빌드해야 안내됨 |
| 배포/복구 | 기존 OneDrive 배포 메뉴·직접 설치 선택지·직전 게시본/로컬 백업 유지 |

## 실기 확인이 필요한 항목

1. 기존 설정과 대표 Excel을 복사한 시험 환경에서 열기·저장·양식·취합·감시·WPH 확인.
2. Windows에서 build.bat 8.1 실행, 파일명·프로그램 정보·PE 속성 버전 일치 확인.
3. 시험용 OneDrive 폴더와 PC 2대로 동기화 지연·동시 편집·충돌본 경고 확인.
4. 구버전→신버전 업데이트, 한글/%/! 경로, 읽기 전용·백업 실패·파일 잠금 실패 확인.
5. 직접 설치 경로 및 백업 복구, 기존 데이터·사용자 설정 유지 확인 후 운영 게시.

## 남은 개선 과제

- equip_app.py에 UI와 업무 조정 코드가 집중됨. 화면별 분리는 별도 회귀 범위가 필요하다.
- 공유 파일의 완전한 동시성 보장에는 현재 OneDrive 파일 모델의 한계가 있다.
- 로컬 설정 저장 실패는 기존처럼 조용히 처리한다. 사용자 경고/복구 UX 개선 여지가 있다.
- tests/test_engine.py는 저장소에 없는 원본 .xlsm에 의존해 일괄 검증에서 제외된다.
- 과거 보안 문서에는 net use 삭제 전 가설과 오래된 패키지·네트워크 설명이 남아 있다.
  최신 제약은 AGENTS.md와 CLAUDE.md의 확정 결정 및 실제 코드를 우선한다.
