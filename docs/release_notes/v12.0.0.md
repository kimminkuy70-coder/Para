# Camtek AOI Manager v12.0.0

**Batch Report 분석**의 가동률 · WPH 지표를 다시 정의했습니다. 개선 레시피(예: `PI Enhanced`)를 돌릴 수 있는 호기가 적어도
기존 레시피(`PI`)보다 하루에 더 많이 처리하는지 비교할 수 있게 했습니다. 레시피는 Batch Report에 적힌 `Job · Recipe(s)`로 구분합니다.
모든 지표 옆 **?** 버튼을 누르면 뜻 · 계산식 · 지금 화면 숫자로 계산한 예 · 확인할 것 · 한계가 나옵니다.

## 시간 3칸 (호기마다 하루 24시간)
- **웨이퍼 처리**: wafer를 넣고 · 스캔하고 · 빼던 시간(로봇 이동 포함). Error · 중단이 없는 Batch Report는 Batch Time 전체,
  있으면 `Pass 장수 × 1장 처리 시간`까지.
- **Error · 중단 및 조치**: Error · 작업자 중단이 있는 Batch Report의 나머지 시간 + 같은 호기에서 같은 Lot을 다시 스캔하기까지
  장비가 아무것도 스캔하지 않은 시간.
- **유휴**: 나머지(물량 없음 · PM · 다운은 구분하지 못합니다).
- 같은 wafer를 다시 스캔한 것도 처리 시간과 장수에 넣습니다(투입 · 출하 정보가 없어 필요한 재스캔인지 알 수 없음 — 재스캔 참고 비율로 따로 표시).

## WPH · 생산능력
- **1장 처리 시간**(로봇 이동 포함)과 **Avg. Scan Time**(Batch Report 원문 값, 순수 스캔)을 나눠 보여 줍니다.
- **정상 WPH** = Error · 중단 없이 25매 모두 Pass한 Batch Report의 장수 합 × 3,600 ÷ Batch Time 합.
- **실제 WPH** = Pass 장수 × 3,600 ÷ (웨이퍼 처리 + Error · 중단 및 조치) — 장비가 놀던 시간만 뺍니다.
- **하루 생산능력** = 24 × 실제 WPH, 레시피 합계 = 그 레시피를 돌린 호기들의 합.
- **레시피 비교**: 레시피마다 호기별 하루 생산능력을 쌓은 막대. 레시피를 고르면 같은 Job의 레시피끼리 비교합니다.
- **호기 × 레시피 표**: 레시피 합계 줄 포함. 누르면 **레시피 상세 창** — WPH 분해(정상 → Error 손실 → 중단 손실 → 실제),
  1장 처리 시간(Avg. Scan Time + 로봇 이동 등), Lot별 실제 WPH.

## 작업자 중단 · 스캔 안 한 슬롯
- 앞에 Error 없이 `Aborted.`로 멈춘 Batch Report는 **작업자 중단**입니다. Error로 세지 않지만 멈춘 시간은 손실로 셉니다.
- 멈출 때 wafer의 Faults가 그 레시피 정상 wafer Faults 상위 1% 값보다 많으면 **Defect 과다 중단**입니다(정상 wafer가 100장 미만인
  레시피는 판정하지 않음). 판정 기준 · 레시피별 기준값 · 이번 조사 판정 목록을 보여 주는 **설명 창**이 있습니다.
- 앞에 Error 없이 `Skipped.`인 행은 **스캔하지 않은 슬롯**으로 보고 wafer로 세지 않습니다.

## 화면
- **가동률**: 숫자 4개 + 호기별 / 기간별 막대. 기간을 누르면 **기간 상세 창**(시간 구성 · 손실 이유 · 24시간 시간표).
- **Lot 추적**: `Error 요약` → **멈춘 이유 요약**(Error / 작업자 중단). Lot 창에 작업자 중단 색과 표시를 넣었습니다.
- 화면 위 설명 카드와 로직 상자는 없애고 ? 버튼으로 옮겼습니다.

## 알아 둘 것
- 기존 결과 파일(분석 HTML/Excel · 가동률 대시보드 · WPH 엑셀/HTML)은 이전 정의 그대로라 앱 화면과 숫자가 다를 수 있습니다.
- 중복 Pass 중 어느 스캔을 쓸지 고르는 개발자 선택은 Dice 합계에만 영향을 줍니다(가동률 · WPH는 다시 스캔한 것도 장수에 넣으므로 같음).
