# 디자인 개편 — 이어서 하기 (2026-11-24 세션 정리)

AOI Manager 화면 디자인 개편 작업의 지금 상태. 다른 세션은 이 파일 → `DESIGN.md` → 예시 HTML 순으로 읽고 이어서 한다.

## 가장 중요한 규칙

1. **예시 파일과 실제 프로그램 화면이 다르면 프로그램이 우선이다.**
   예시 HTML(`docs/design/AOI_Manager_디자인_예시.html`)은 모양 · 색 · 움직임을 보여 주는 그림이다. 기능 · 화면 구성 · 글 · 단계 · 선택지 · 숫자는 실제 프로그램(`frontend/src/*.tsx`, Defect 분석 HTML rev6)을 따른다.
   예시에서 가져오는 것은 **겉모습과 움직임만**이다. 아래 '예시 ≠ 프로그램' 표를 볼 것.
2. 디자인 작업은 기능을 바꾸지 않는다 — 클래스 이름 · DOM · `data-tour` · 화면 글 · 엔진은 그대로(`DESIGN.md` 1절).
3. 우선순위 = 소유자 말 → `CLAUDE.md` → `DESIGN.md` → 예시 HTML.
4. 아직 프로그램 코드(`styles.css` · `*.tsx` · `para-skin.css`)에는 **하나도 적용하지 않았다.** 소유자 피드백을 받는 중이다.

## 파일

| 파일 | 무엇 |
|---|---|
| `DESIGN.md`(저장소 맨 위) | 디자인 기준 초안(`status: draft`). 토큰 · 글자 · 모서리 · 그림자 · 움직임(8절) · 부품 대응표(10절) · 정할 것(14절) |
| `docs/design/AOI_Manager_디자인_예시.html` | 예시 화면 · 컴포넌트 모음. 브라우저로 바로 열림(외부 파일 · 인터넷 없음). 맨 위 줄로 페이지 고르기, [새 디자인 / 지금 디자인] 비교 |
| 이 파일 | 이어서 하기 · 예시와 프로그램 차이 · 남은 일 |

예시 HTML 은 claude.ai 아티팩트로도 올려 두었다(소유자 계정, 비공개) — 링크는 그 세션 기록에 있다. 저장소의 파일이 기준이다.
예시를 고치면 이 파일도 같이 고치고, 아티팩트를 다시 올리려면 저장소 파일에서 맨 앞 `<!doctype>` · `<head>` 머리와 `<body>` 껍데기를 빼고 올린다(아티팩트가 껍데기를 붙인다).

## 소유자가 정한 것 (2026-11-24)

- 색 · 톤은 지금 프로그램 그대로: 구조 = 슬레이트(`#37474f`), 강조 = 에메랄드(`#10b981`), 바탕 = 회청색. 토스 TDS design.md 의 **구조**만 빌림(파랑 · Pretendard · 해요체 · 모바일 패턴은 안 빌림).
- 'Thinking sphere'(기다림 구)는 **삭제**.
- 움직임은 화면 전체가 부드럽게. 단 렉이 생기면 그 움직임은 뺀다(transform · opacity 만, 멈추면 계산도 멈춤).
- 모션 부품 다섯 가지 적용(원본 코드를 읽고 같은 타이밍으로 다시 만듦, 추가 패키지 없음):
  ① 단계 표시 = designbookmark `step-progress`, ② 작업 단계 = Kokonut UI `ai-loading`(MIT), ③ 돌림 선택 = Kokonut UI `wheel-picker`(MIT),
  ④ 값 끌어 고르기 = SmoothUI `scrubber`(MIT), ⑤ 복사 = designbookmark `copy-button`. 값은 `DESIGN.md` 머리말 `motion.springs` · 8-2절.
- Defect 분석 필터 = **양방향(최소 · 최대 손잡이 2개) + 숫자 직접 입력**, 기본 · 대규모 두 모드에 같은 부품.
- Wafer Map 으로 필터에 맞는 Defect 를 고르는 것은 **Defect 분석(기본)** 에 둔다. 대규모(Step 5)는 지도 없이 목록.

## 예시 ≠ 프로그램 (프로그램이 우선)

| 곳 | 예시 HTML | 실제 프로그램 — 이쪽을 따른다 |
|---|---|---|
| 전체 | 숫자 · Lot · 경로 · 사진 · 시각은 지어낸 예시, 글 일부를 짧게 바꿈 | 엔진이 주는 실제 값 · 지금 화면 글(디자인 작업에서 글을 바꾸지 않음) |
| 전체 | 미리보기 도구 줄 · 창 틀(제목 막대) · 기능 탭의 ● 표시 · '지금 디자인' 비교 모드 · 자동 시연 | 없음(예시 전용) |
| 전체 | 맑은 고딕이 없으면 대체 서체로 보임 | Windows 맑은 고딕 |
| Batch Report 분석 | 열면 조사가 한 번 혼자 돈다. 작업 단계의 단계 이름 · 기록 줄은 예시 | 조사는 [조사 시작]을 눌러야 돈다. 단계 · 기록 글은 엔진 진행 메시지로 정한다 |

새로 차이를 찾으면 이 표에 더한다.

## 남은 일

1. 소유자 피드백 받기 — 예시 HTML 을 보고(`DESIGN.md` 14절의 정할 것 9개 포함).
2. 피드백이 끝나면 `DESIGN.md` 의 `status: draft` 를 지우고 확정.
3. 프로그램에 적용(`DESIGN.md` 1절 순서): `styles.css` `:root` 토큰(옛 이름은 별칭으로) → 공통 부품 → 화면별 범위(`.bv` · `.kla` · `.tb5` · `commonality.css`) → `para-skin.css` →
   모션 부품(`frontend/src/motion.ts` 스프링 함수 + React 부품, 추가 패키지 없이) → `npm run build` 후 `frontend/dist` 커밋 → 시험(`tests/test_*.py`, `tools/test_desktop_ui.mjs`) →
   전 · 후 스크린샷(모든 탭 + Mini 창).
4. Defect 지도 영역 고르기는 소유자가 넣기로 하면 별도 작업으로.

## 작업 환경 메모

- 이 세션의 클라우드 환경 'Para'(개인) 는 원본 코드를 읽으려고 `designbookmark.com` · `kokonutui.com` · `smoothui.dev` 를 허용해 두었다. 원본 코드를 다시 볼 일이 있으면 그 환경에서.
- 예시 HTML 은 브라우저(Playwright)로 모든 페이지를 눌러 봤고 오류 0, 끌기 중 50ms 넘는 멈춤 없음, 폭 390 에서 가로 밀림 없음(2026-11-24).
