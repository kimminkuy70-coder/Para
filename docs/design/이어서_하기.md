# 디자인 개편 — 이어서 하기 (2026-11-24 세션 정리 · 같은 날 소유자 결정 반영)

AOI Manager 화면 디자인 개편 작업의 지금 상태. 다른 세션은 이 파일 → `DESIGN.md` → 예시 HTML 순으로 읽고 이어서 한다.

## 가장 중요한 규칙

1. **예시 파일과 실제 프로그램 화면이 다르면 프로그램이 우선이다.**
   예시 HTML(`docs/design/AOI_Manager_디자인_예시.html`)은 모양 · 색 · 움직임을 보여 주는 그림이다. 기능 · 화면 구성 · 글 · 단계 · 선택지 · 숫자는 실제 프로그램(`frontend/src/*.tsx`, Defect 분석 HTML rev6)을 따른다.
   예시에서 가져오는 것은 **겉모습과 움직임만**이다. 아래 '예시 ≠ 프로그램' 표를 볼 것.
2. 디자인 작업은 기능을 바꾸지 않는다 — 클래스 이름 · DOM · `data-tour` · 화면 글 · 엔진은 그대로(`DESIGN.md` 1절).
3. 우선순위 = 소유자 말 → `CLAUDE.md` → `DESIGN.md` → 예시 HTML.
4. **작업 브랜치 = `design_rebuild`**(소유자 2026-11-24, `version_v14` 에서 만듦). 여기서 모두 고친 뒤 `version_v14` 의 다음 판으로 옮긴다 — 옮기는 것은 소유자가 말할 때만.
   `design_rebuild` push 는 CI(v14.yml)를 돌리지 않으므로 시험은 직접 돌린다. 진행 상황 = 아래 '진행'.

  원통을 돌리면 원래 setter 로 값을 넣고 change 이벤트 → React onChange. React 가 값을 바꾸면 0.4초마다 따라감. 붙일 곳 = `data-wheel` 속성만.
- 탭 밑줄은 화면 코드를 고치지 않고 `startMotion()`(main.tsx)이 `.navigation · .subtabs · .bv .maintabs · .watch-tabs · .defect-tabs` 에 붙는다(분절 = `.bv .pilltabs · .bv .seg`).
  고른 탭 = `.active` · `.on` · `[aria-selected=true]`. 붙으면 그 줄의 단추 밑줄은 투명(`.has-ink`).
- 범위 막대가 들어가며 5-1 값 범위는 **한 줄에 하나**(v14.1.5 '값 범위 4개 한 줄'을 대신함 — 막대가 들어갈 자리). 시험도 그렇게 바꿈.
- 5-2 · 5-3 목록은 5-1 에서 넘어온 Defect 안에서만 거른다(범위를 넓혀도 늘지 않음 — 필터 카드에 안내 `#bigFltNote`). 필터에 맞는 것이 없으면 5-3 탭은 잠김(종전 규칙).
- rev6 HTML 을 고쳤으므로 원본(ccr 브랜치)과 달라졌다 — v14.4.1 처럼 원본은 그대로 두었다.
