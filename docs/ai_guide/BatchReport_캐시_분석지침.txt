==========================================================================================
 Camtek AOI Manager — Batch Report 캐시 분석 지침 (새 AI 전달용)
 기준 코드: version_v12 브랜치, 앱 v12.2.8 (2026-10-07 작성, 이슈 #17)
==========================================================================================

이 문서를 [Batch Report 캐시 내보내기 (zip)] 로 만든 zip 파일과 함께 AI 에게 주세요.
AI 는 이 문서의 계산 방식을 "그대로" 써서 질문에 답해야 합니다. 프로그램(앱 화면 · 결과 HTML ·
Excel)이 내는 숫자와 같은 숫자가 나와야 하며, 새 지표를 마음대로 정의하면 안 됩니다.

------------------------------------------------------------------------------------------
 0. AI 에게 주는 기본 지시 (그대로 복사해서 써도 됨)
------------------------------------------------------------------------------------------
- 첨부 zip 은 Camtek AOI 장비 Batch Report(스캔 1번 = HTML 1장)를 프로그램이 읽어 모아 둔
  캐시다. 이 지침의 정의 · 순서 · 예외 규칙을 그대로 따라 계산하라.
- 숫자는 반드시 zip 안 데이터로 직접 계산하고(코드 실행 가능하면 Python 표준 라이브러리로),
  추정 · 기억 · 일반론으로 채우지 마라. 계산 불가한 값은 "계산 불가(이유)"라고 써라.
- 표시하는 오류 문구는 Batch Report 원문(Pass/Fail 칸) 그대로 쓴다. 요약 · 번역 · 의역 금지.
- 답할 때는 범위(호기 · 기간 · 레시피)와 사용한 정의(예: "실제 WPH = Pass 장수×3600÷(처리+손실)")
  를 함께 적어라.
- 이 숫자들은 참고 지표(proxy)다. 장비 설정을 자동으로 바꾸는 근거로 쓰지 않는다.
- 데이터에 없는 정보(투입 계획 · 출하 · PM · 전원 OFF · 실제 수리 시간)는 알 수 없다고 말하라.

------------------------------------------------------------------------------------------
 1. zip 구조
------------------------------------------------------------------------------------------
BatchReport_캐시_YYYYMMDD_HHMMSS.zip
 ├─ manifest.json
 │    {schema:1, exported_at, app_version, cache_schema:1, machines(호기 수), reports(총 Report 수),
 │     files:[{file:"누적/<호기>_<해시8>.json", machine, folder(장비 원본 폴더), reports}]}
 ├─ 누적/<호기>_<해시8>.json        ← 호기 × 원본 폴더 하나당 1개 (한 호기에 폴더가 여럿이면 여러 개)
 └─ 사람선택/batch_lot_choices.json ← (있을 때만) 중복 Pass wafer 에 대해 사람이 고른 Batch Report

누적/*.json 형식(schema 1):
  {
    "schema": 1,
    "machine": "AOI-21",                         ← 호기 이름
    "folder":  "P:\\AOI-21\\Reports",            ← 원본 폴더
    "entries": {
      "<Batch Report 파일명>.htm": {
        "signature": [수정시각_ns, 크기],         ← 계산에 쓰지 않음
        "digest": "<sha256>",                    ← 내용 해시(파일명 제외). 중복 제거에 사용
        "report": {
          "file_name": "<파일명>",
          "metadata": [["Batch Start","30-Aug-26 09:41:31 PM"], ["Batch End", ...],
                       ["Batch Time","00:53:23"], ["Wafers Scanned","25"],
                       ["Avg. Scan Time","00:01:44"], ["Job/Setup","<Job>/<Setup>"], ...],
          "wafers": [ {"No":..., "Lot":..., "Wafer ID":..., "Faults":..., "Scanned Dice":...,
                       "Bad Dice":..., "Good Dice":..., "Yield":..., "Pass/Fail":...,
                       "Recipe(s)":...}, ... ],      ← 웨이퍼 표 1행 = dict 1개(원래 행 순서)
          "table_count": n
        }
      }, ...
    }
  }

  * metadata 는 [이름, 값] 쌍의 목록이다(HTML 의 BATCH_INFO 표를 2칸씩 짝지은 것).
  * 웨이퍼 표 열 이름은 장비마다 조금 다를 수 있다 → 아래 2장의 "이름 정규화"로 찾는다.

레코드 만들기(프로그램과 같게):
  - 각 캐시 파일의 entries 를 순서대로 레코드로 만든다.
    record = {id: "<캐시파일 해시64>:<파일명>", machine, source_folder: folder, report}
    (zip 파일명에는 해시 앞 8자만 있다. id 는 정렬의 동점 처리와 사람선택 매칭에만 쓰이므로
     "<해시8>:<파일명>" 으로 써도 결과는 같다. 사람선택 매칭은 1장 마지막 항목 참고.)
  - 같은 호기 안에서 digest 가 같은 Report(백업 폴더의 동일 내용)는 처음 것 하나만 쓴다.
  - 프로그램은 화면의 조사 범위(호기 · 검색어 · 기간)에 맞는 Report 만 쓴다. zip 에는 캐시
    전체가 들어 있으므로, 사용자가 범위를 말하면 그 범위로 거른다.
    · 검색어: 파일명(소문자, 공백 정리)에 검색어의 모든 단어가 포함(AND).
    · 기간: 파일명 안 날짜 `_YY-Mon-DD_(HH.MM.SS)_` 기준(예: _26-Aug-30_(21.41.39)_).

batch_lot_choices.json:
  {"schema":1, "choices": {"<묶음 key>\t<wafer key>": "<고른 Batch Report id>", ...}}
  - 묶음 key = 그 묶음의 첫 Batch Report id(시간순), wafer key = "S07"(슬롯) 또는 "ID:<Wafer ID>".
  - id = "<해시64>:<파일명>". zip 에서는 "<해시 앞 8자> + 파일명"이 같은 레코드로 매칭한다.
  - 사람 선택은 "중복 Pass wafer 의 Dice 를 어느 Report 에서 가져올지"만 바꾼다(5장).

------------------------------------------------------------------------------------------
 2. 공통 파싱 규칙
------------------------------------------------------------------------------------------
- 이름 정규화 normalize_key(x) = 소문자로 바꾸고 영문 · 숫자 외 문자를 모두 지움.
  예: "Pass/Fail" → "passfail", "Wafers Scanned" → "wafersscanned", "Job/Setup" → "jobsetup".
- metadata 조회: {normalize_key(이름): 값} 사전에서 batchstart, batchend, batchtime,
  wafersscanned, avgscantime, jobsetup 을 찾는다.
- 웨이퍼 칸 조회(safe_field): 여러 후보 이름 중 정규화해서 처음 맞는 칸.
    상태 = "Pass/Fail" → "Status" → "State"
    레시피 단계 = "Recipe(s)" → "Recipe"
    그 외 "Lot", "Wafer ID", "Faults", "Scanned Dice", "Bad Dice", "Good Dice", "Yield"
- 문자열 정리 clean_text: HTML 엔티티 해제, NBSP → 공백, 연속 공백 1개, 앞뒤 공백 제거.
- 시간 "HH:MM:SS"(또는 "MM:SS") → 초. 못 읽으면 없음(None).
- 날짜 "30-Aug-26 09:41:31 PM" → 2026-08-30 21:41:31 (2자리 연도 +2000, 월은 영문 약어, AM/PM 처리).
- 숫자: 쉼표 · % 제거 후 실수. 음수 · 무한대 · 못 읽음 → None.
- Good Dice 가 비어 있으면 Scanned − Bad 로 보정(둘 다 있을 때).

------------------------------------------------------------------------------------------
 3. 시도 = Batch Report 1장 (lotmodel.attempt)
------------------------------------------------------------------------------------------
대전제: Lot 1개 = Batch Report 1장이 아니다. Error 재스캔 · 나눠 스캔 · 호기 이동으로 여러 장에
나뉜다. 그래서 "시도(Report 1장) → 묶음(한 번의 검사를 끝내려고 이어서 한 시도들) → Lot" 으로 묶는다.

3-1. 기본 값
  job_setup = clean(Job/Setup),  job = "/" 앞,  setup = "/" 뒤
  start = Batch Start, end = Batch End, batch_sec = Batch Time(초),
  avg_scan_sec = Avg. Scan Time(초), wafers_scanned = Wafers Scanned
  step(공정 단계) = 웨이퍼 표 Recipe(s) 칸의 최빈값(빈 값 제외). 없으면 "".

3-2. S/M
  파일명 끝의 "_YY-Mon-DD_(HH.MM.SS)_BatchReport.htm(l)" 을 떼고, 그 앞이 "<job>_<setup>_" 로
  시작하면 그 뒤 문자열이 S/M.
  예: "…0A_6392_KDT-PR RW_26-May-06_(…)_BatchReport.htm" → S/M = "KDT-PR RW"
  형식이 다르면: 웨이퍼 Lot 칸의 최빈값(빈칸 · "-" · "LoadPort…" 제외).

3-3. Lot 코드 · 스캔 종류
  Lot 코드 = S/M 안에서 처음 나오는 "단독 영문 3글자"(앞뒤가 영문이 아님), 대문자로.
    "BAW-0911S" → BAW,  "0701 N SPT …" → SPT,  "0, FOCUS" → 없음
  Lot 코드가 없으면 "점검 스캔" — Lot 에서 빼고(excluded), 가동률에서 "점검" 시간으로만 센다.
  3D 스캔 = S/M 에 단독 "3D"(앞뒤가 영숫자가 아님, 예 "ABC-3D")가 있으면 3D, 아니면 2D.

3-4. Lot ID (Wafer ID 기반)
  Wafer ID 가 정규식 ([A-Z0-9]{5})(\d{2})-[A-Z0-9]{2} 에 "전체 일치"하면(예 SF14G25-A0)
  앞 5자(SF14G)가 Lot ID, 다음 2자리(25)가 슬롯.
  "판독 오차 허용": 길이가 같고 1글자 이하 다르면 같은 ID(SH47T ≈ SA47T).
  묶기(_cluster): 많이 나온 순서대로 보며, 기존 대표와 1글자 이하 차이면 그 그룹에 넣고
  아니면 새 대표. 시도의 lot_id = 첫 번째 대표(가장 많이 나온 것).

3-5. 슬롯
  웨이퍼 표가 정확히 25행이면 1행 = 25번, 2행 = 24번 … 25행 = 1번(장비가 25→1 순서로 스캔).
  아니면 Wafer ID 에서: "Slot 14" · "14" 형식(1~25) 또는 위 전체 ID 의 슬롯 2자리. 모르면 None.

3-6. 웨이퍼 행 원인(cause) 판정
  Pass = 상태가 정확히 "Pass" / "Pass." / "Pass!" (대소문자 무시). 그 외는 전부 Error 후보(빈칸 포함).
  원인 유형 표(원문 문구 → 유형):
    "Wafer Map Import failed."  → 맵 Import 오류
    "Scan 2D Error."            → 2D Scan 오류
    "Alignment Error."          → Alignment 오류
    "Failed to read wafer id."  → Wafer ID 판독 오류
    "Nothing to Scan."          → 검사 대상 없음
    "Aborted."                  → 작업 중단
    "Skipped."                  → 검사 제외
    "Clean Reference Error."    → Clean Reference 오류
    "Focus Mapping Error."      → Focus Mapping 오류
  - 상태 칸에 문구가 여럿이면 "원문에서 가장 앞에 나온 문구"가 그 행의 원인.
  - 빈칸 → 유형 "상태 없음", 문구 "(빈 칸)".  표에 없는 문구 → 유형 "미분류", 문구 = 원문 전체.

3-7. 행 종류(kind) — 순서대로 한 행씩 본다
  has_error = 이 Report 에 "작업 중단 · 검사 제외가 아닌" 원인이 하나라도 있는가.
  trigger(첫 Error) = 없음, stopped = 거짓 으로 시작.
  각 Error 후보 행에 대해:
   a) 아직 trigger 도 없고 stopped 도 아닌데 원인이 "검사 제외"(Skipped.) → kind "스킵"
      = 스캔 안 한 슬롯. wafer 로 세지 않는다.
   b) has_error 가 거짓이고 (이미 stopped 이거나 원인이 "작업 중단") → kind "중단", stopped = 참
      = 작업자 중단(Error 아님). 그 뒤 Skipped 도 중단으로 스캔 못 한 wafer.
   c) 그 외: 원인이 작업 중단/검사 제외이고 앞에 trigger 가 있으면 kind "연쇄"(원인 = 앞 첫 Error),
      아니면 kind "원인"(직접 Error). trigger 가 비어 있으면 이 행이 trigger 가 된다.
  Report 결과(outcome):  has_error → "Error",  아니고 중단 행이 있으면 → "중단",  아니면 → "정상".

3-8. 멈출 때 Faults(stop_faults, outcome = 중단 일 때만)
  첫 "중단" 행 앞의 Pass 행 중 마지막 행의 Faults + 모든 "중단" 행의 Faults 중 최댓값(값 없으면 None).

------------------------------------------------------------------------------------------
 4. 묶음과 Lot (lotmodel.build)
------------------------------------------------------------------------------------------
상수: 같은 호기 간격 12시간(SAME_MACHINE_GAP_H), 호기 이동 최대 48시간(MOVE_GAP_H), 25 슬롯.

4-1. Lot 코드별로 시도를 모은다(점검 스캔 제외). 2D 와 3D 는 따로 처리한다(서로 재스캔 · 중복 아님).
4-2. 묶음 나누기: 시도를 (start, 없으면 end) → id 순으로 정렬해 하나씩 본다.
     직전 묶음의 끝 = 그 묶음 시도들의 max(end, 없으면 start).  gap = 이번 start − 직전 묶음 끝.
     묶음의 공정 단계 = 묶음 안 시도들의 step 중 가중치 최대(가중치 = 1 + Pass 행 수 × 100).
     same_step = 묶음 단계가 비었거나, 이번 step 이 비었거나, 둘이 같음.
     - 직전 묶음의 마지막 시도와 같은 호기: gap ≤ 12h 이고 same_step → 같은 묶음.
     - 다른 호기: gap ≤ 48h 이고 same_step 이고 직전 묶음에 "Pass 없음" wafer 가 남아 있으면
       → 같은 묶음(호기 이동 재스캔, moved = 참).
     - 그 외 → 새 묶음.  (gap 이 음수여도 위 조건을 만족하면 같은 묶음)
4-3. 한 묶음 안에 Lot ID 대표가 둘 이상이면 Lot ID 별로 나눈다. Lot ID 없는 시도는 시간상
     가장 가까운 쪽에 붙인다.
4-4. Lot = (Lot 코드, Lot ID 대표). 그 코드에 Lot ID 대표가 하나뿐이면 ID 없는 묶음도 그 Lot 에
     넣고, 둘 이상이면 ID 없는 묶음은 "코드 · Lot ID 미확인" Lot 으로 따로 둔다.
     Lot 표시 이름: ID 가 여럿인 코드면 "코드 · ID", 아니면 "코드".
4-5. Lot 상태: Pass 없음 wafer 가 있으면 "Pass하지 못한 wafer 존재",
     아니고 재스캔 Pass wafer 가 있으면 "재스캔으로 완료", 아니면 "한 번에 완료".

------------------------------------------------------------------------------------------
 5. 묶음 안 wafer 최종 판정 (lotmodel.resolve)
------------------------------------------------------------------------------------------
- wafer key: 슬롯이 있으면 "S07" 형식. 없으면 같은 묶음에서 그 Wafer ID(실제 ID, "Slot N"·숫자만은
  아님)에 슬롯이 알려져 있으면 그 슬롯, 아니면 "ID:<Wafer ID>". "스킵" 행은 넣지 않는다.
- 같은 key 의 행들(묶음 안 시도 순서대로)에서:
    Pass 없음 → "Pass 없음"
    Pass 2번 이상 → "중복 Pass"
    Pass 1번 + Error 있음 → "재스캔 Pass"
    Pass 1번만 → "한 번에 Pass"
- Dice 를 가져올 행(pick) = 가장 나중 Pass. 사람선택에 (묶음 key, wafer key) 가 있고 그 시도가
  이 wafer 에 있으면 그 행으로 바꾼다.
- 묶음 Dice 합계 = pick 이 Pass 인 wafer 의 Scanned · Bad · Good 합(셋 중 하나라도 없으면 missing 으로
  세고 합에서 뺌). 묶음 Yield = Good 합 ÷ Scanned 합 × 100.
- wafer 의 원인(표시) = 직접 Error("원인" 행)의 원문 문구 → 없으면 연쇄 행의 trigger 문구 →
  없으면 중단 행 문구("Aborted."). Error 없이 중단만 있었던 wafer 는 stop = 참(Error 집계에서 뺀다).

------------------------------------------------------------------------------------------
 6. 레시피와 기준값 (batchview)
------------------------------------------------------------------------------------------
- 레시피(WPH · 기준값 단위) = "<job> · <step>" (3D 스캔이면 "<job> · <step> · 3D 스캔", step 이 없으면 "—").
- 정상 25매 Report(is_normal) = outcome 정상 + 웨이퍼 표 정확히 25행 + 25행 모두 Pass + batch_sec > 0.
- 1장 처리 시간(초) — Lot 으로 묶인 시도만 사용(점검 스캔 제외):
    unit_n25[키]   = 정상 25매 Report 의 Batch Time 합 ÷ (25 × 장수)
    unit_clean[키] = outcome 정상 Report 의 Batch Time 합 ÷ Pass 행 수 합
    키 우선순위: unit_n25[(호기, 레시피)] → unit_n25[레시피] → unit_clean[(호기, 레시피)] → unit_clean[레시피]
- Defect 과다 기준(레시피별) = outcome 정상 Report 의 Pass 행 Faults 값들의 상위 1%
  (Python statistics.quantiles(값, n=100)[98], 기본 exclusive 방식). 값이 100개 미만이면 기준 없음.
- 작업자 중단 종류: stop_faults > 기준 이면 "작업자 중단 · Defect 과다"(d), 아니면(기준 없음 포함)
  "작업자 중단 · 그 외"(o).

------------------------------------------------------------------------------------------
 7. 가동률 — 시간 3칸 (일 단위 U 행)
------------------------------------------------------------------------------------------
호기마다 하루 24시간 = 웨이퍼 처리 + Error·중단 및 조치(손실) + 유휴.

7-1. Report 1장의 Batch Time 나누기(split)
  - outcome 정상: 처리 = batch_sec, 손실 = 0.
  - 그 외: t = 1장 처리 시간(6장). t 가 없으면 t = batch_sec ÷ (Scanned Dice 값이 있는 행 수).
    처리 = min(batch_sec, Pass 행 수 × t),  손실 = batch_sec − 처리.
7-2. 시각 구간(_span): start ~ end (end 가 없거나 start 이하이면 start + batch_sec).
     자정을 넘기면 달력 날짜별로 시간 비율만큼 나눠 넣는다(day_parts).
7-3. 손실 나누기(loss)
  - outcome 중단: 종류 d/o 칸에 손실 시간 전부, Batch Report 수는 시작일에 1.
  - outcome Error: 그 Report 의 Error 행("원인" · "연쇄")을 원문 문구로 센다
    (원인 행 = 그 문구, 연쇄 행 = 앞 trigger 문구, 비면 "(빈 칸)"). 손실 시간을 문구별 행 수 비율로
    나눠 넣고, 건수(wafer 수)는 시작일에만 더한다.
7-4. 조치 대기: 같은 묶음에서 outcome 이 정상이 아닌 시도 다음 시도가 "같은 호기"이고 다음 시작 >
     이번 끝이면, 그 사이 시간 중 그 호기가 아무 Report 도 스캔하지 않은 시간(그 호기 모든 Report
     구간을 합쳐 뺀 나머지)을 날짜별로 7-3 과 같은 방식(중단이면 d/o, Error 면 문구 비율)으로 손실에 더한다.
7-5. 점검 스캔(Lot 코드 없는 Report)은 Batch Time 전체를 날짜별로 "점검"(ck) 처리 시간에만 더한다.
7-6. U 행 = (날짜, 호기, 레시피)별 합계:
    p   웨이퍼 처리 초          du  그중 이미 Pass 한 wafer 를 다시 스캔한 몫(처리 × 중복수 ÷ Pass 수)
    ck  점검 스캔 초            e   {Error 원문: [손실초, wafer 건수, Lot 목록]}
    sd  Defect 과다 중단 [초, Report 수, Lot]   so  그 외 중단 [초, Report 수, Lot]
    n   시작 Report 수          ne  Error Report 수        ps  Pass wafer 수(중복 Pass 도 포함)
    dn  다시 스캔해 또 Pass 한 수  w25 정상 25매 장수(25×개수)  s25 정상 25매 Batch Time 합
    aw/asum  정상 25매의 Avg. Scan Time 가중합(장수 25 기준)
  (n · ps · dn · ne · w25 · s25 · aw · asum 은 스캔 시작일에만 더한다.)
7-7. 기간 합산(앱 · 결과 HTML 과 같음)
    범위 = 조사 결과의 처음 ~ 마지막 Batch Report 시작 날짜(양 끝 포함, 빈 날도 셈)
    달력 시간 = 날짜 수 × 86400 × 호기 수(호기별이면 호기 1대)
    처리 = Σp + Σck,  손실 = Σe + Σsd + Σso,  유휴 = max(0, 달력 − 처리 − 손실)
    가동률(%) = 처리 ÷ 달력 × 100,  손실(%) = 손실 ÷ 달력 × 100,  유휴(%) = 유휴 ÷ 달력 × 100
    주 = ISO 주(월요일 시작, "YYYY WWn (MM/DD~MM/DD)"), 월 = YYYY-MM.

------------------------------------------------------------------------------------------
 8. WPH · 생산능력 (앱 기준 정의)
------------------------------------------------------------------------------------------
  정상 WPH      = Σw25 × 3600 ÷ Σs25           (정상 25매 Report 만)
  실제 WPH      = Σps × 3600 ÷ (Σp + 손실)      (유휴만 뺀 시간. 점검 ck 는 넣지 않음)
  1장 처리 시간 = Σs25 ÷ Σw25 (초)
  순수 스캔     = Σasum ÷ Σaw (초, Avg. Scan Time)
  하루 생산능력 = 24 × 실제 WPH
  처리량 감소(%) = (1 − 실제 WPH ÷ 정상 WPH) × 100
  재스캔 참고 비율: 같은 wafer 를 다시 스캔해 또 Pass 한 것(dn, du)도 장수에 들어간다.
    투입 · 출하 정보가 없어 필요한 재스캔인지 판단할 수 없으므로 비율로만 보여 준다.
  합산 범위: 레시피 · 호기 · 기간을 고르면 해당 U 행만 더한다(n > 0 인 칸만 표시).

------------------------------------------------------------------------------------------
 9. Lot 추적 화면 숫자
------------------------------------------------------------------------------------------
  Lot Scan 완료 = Lot 수,  Batch Report 존재 = 전체 Report 수(그중 점검 스캔 수 따로)
  재스캔으로 완료된 Lot / Pass하지 못한 Lot = 4-5 상태별 Lot 수
  중복 Scan wafer 가 있는 Lot = 중복 Pass wafer 가 1개 이상인 Lot 수
  멈춘 이유 요약 · Error: Lot 마다 wafer 원인 문구별 wafer 수(cz). 문구별로
    [Lot 수, 재스캔해서 Pass 한 Lot, Pass 못 한 Lot(그 문구 wafer 중 Pass 없음 존재), wafer 수].
  멈춘 이유 요약 · 작업자 중단: 종류(d/o)별 같은 형식 + 중단 Report 수.
  (중단만 있었던 wafer 는 Error 원인에 넣지 않고 중단 쪽에만 센다.)

------------------------------------------------------------------------------------------
 10. 레시피 비교 모드 (recipecompare, A=기존 · B=신규)
------------------------------------------------------------------------------------------
- 비교 키 = "<Job/Setup 의 '/' 앞> · <Recipe(s) 최빈값>" (Recipe(s) 없으면 "(Recipe 없음)").
- Report 마다: 상태가 "Skipped" 로 시작하는 행은 제외, n = 나머지 행 수, ok = 상태가 정확히 "Pass" 인 행,
  err = 그 외 상태 원문 목록. 시작 = Batch Start(없으면 Batch End). bt = Batch Time 초.
- 테스트 Lot: Lot 칸 이름에 test / engineer / scan time / "0" / "t" / loadport 가 있으면 테스트.
  단 영문 3글자로 시작하는 실제 Lot 이름(테스트 문구 없음)이 하나라도 있으면 테스트 아님.
- 정상 Report = bt > 0 이고 err 없음 이고 ok = n > 0.
    wph25     = 3600 × Σn ÷ Σbt (정상 Report 중 n = 25)
    wph_clean = 3600 × Σn ÷ Σbt (정상 Report 전체)
    wph_all   = 3600 × Σok ÷ Σbt (모든 Report, 오류 포함)
    순수 스캔 = 정상 Report Avg. Scan Time 중앙값,  1장 처리 = 정상 Report Σbt ÷ Σn
    오류율 = 오류 행 수 ÷ Σn, 그중 작업자 중단 · Skip(첫 문구가 Aborted / Wafer aborted by user /
    Skipped) 과 레시피 탓 오류로 나눔. 오류 원인 = 상태 원문의 첫 "." 앞.
- 기본 범위: 테스트 Lot 제외, 같은 호기(A · B 모두에 있는 호기만).
- 검출력: 같은 실제 Wafer ID(6자 이상, 영문+숫자, "slot" 시작 아님)를 A 와 B 에서 모두 Pass,
  Scanned Dice 같음, 시작 시각 차이 pair_hours(기본 72h) 이내인 쌍(가장 가까운 A). 쌍마다 Bad Dice 비교,
  부호 검정 p = min(1, 2 × Σ_{i≤min(up,dn)} C(n,i) ÷ 2^n). p < 0.05 이면 "B가 더/덜 많이 잡음", 아니면 "차이 없음".
- 결론 안정성: WPH 기준 3 × 테스트 제외/포함 × 같은 호기/전 호기 = 12 조합의 B ÷ A.
  모두 > 1.02 "B가 빠름", 모두 < 0.98 "B가 느림", 모두 0.98~1.02 "비슷함", 섞이면 "기준에 따라 달라짐".

------------------------------------------------------------------------------------------
 11. (보조) 분석 HTML · Excel 의 M 지표 (batchreport.compute — Lot 모델과 별개인 옛 표)
------------------------------------------------------------------------------------------
  여기서는 Report 의 Lot = 웨이퍼 Lot 칸 최빈값(LoadPort · 빈칸 · "-" 제외, 없으면 "(미상)"),
  lot_key = (Job/Setup 전체, Lot). recipe = Job/Setup 의 "/" 앞.
  M01 WPH: Wafers Scanned = 25(설정값) 이고 Batch Time > 0 인 Report 만.
       합산 WPH = Σwafers × 3600 ÷ Σbatch_sec,  평균 WPH = 각 Report (wafers × 3600 ÷ batch_sec) 의 평균.
  M02 스캔 가동률: Batch Time 을 시작~끝 구간 비율로 일/주/월 버킷에 배분 ÷ 버킷 길이(진행 중이면 지금까지).
       배치 간 gap = 같은 호기 다음 시작 − 앞 Report 끝(분), 음수 = 겹침.
  M03/M04 유형 · 성격(예방형: 맵 Import · 2D Scan · Wafer ID 판독 · 검사 대상 없음 / 조치형: Alignment ·
       Clean Reference · Focus Mapping / 중단 / 결과형: 검사 제외 / 미확인) — 한 행에 여러 문구면 모두 셈.
  M05 Aborted: Report 안 첫 이슈(검사 제외 · 상태 확인 불가 제외) 뒤의 Aborted = 연쇄 추정, 그 전 = 직접 추정.
  M06 재시작 간격: 이슈 Report 끝 → 같은 lot_key 다음 Report 시작(분), 0~1440 만 유효. 평균 · 중앙 · P95
       (Excel PERCENTILE.INC 와 같은 선형 보간) · 최대.
  M08 정상(Pass) wafer 의 Job/Setup · Lot 별 Scanned/Bad/Good 통계.
  M10 Lot 이슈율: lot_key 별 이슈 Lot · 재스캔(Report ≥ 2) Lot 비중.  M11 미분류 · 빈 상태 목록.
  ※ 앱의 가동률 · WPH · Lot 추적 화면 숫자는 6~9장 정의가 기준이다. 사용자가 "앱 화면 숫자"를
    물으면 6~9장으로 답하고, M 지표는 사용자가 분석 Excel/HTML 표를 물을 때만 쓴다.

 12. 주의 · 하지 말 것
------------------------------------------------------------------------------------------
- 캐시에는 장비 원본에서 이미 사라진 Report 도 남아 있을 수 있다(누적). 범위를 말할 때 감안.
- 원본 폴더에 접근하지 못한 날이 있으면 그 기간은 완전한 설비 이력이 아니다.
- 가동률 · WPH 는 Batch Report 만으로 만든 proxy 다. OEE 가 아니며 대기 · PM · 전원 OFF 를 구분하지 못한다.
- "조치" 시간은 같은 Lot 재스캔 전까지 장비가 놀던 시간일 뿐, 실제 수리 시간이 아니다.
- 오류 문구를 "정렬 오류" 처럼 번역 · 축약하지 말고 원문(예 "Alignment Error.")을 함께 보여라.
  (유형 이름은 내부 분류이고, 표시는 원문 기준이 프로그램 규칙이다.)
- 중복 Pass 의 Dice 는 "가장 나중 Pass + 사람선택"만 쓴다. 평균 내거나 둘 다 더하지 않는다.
- 2D 와 3D 스캔은 섞어서 재스캔 · 중복으로 세지 않는다.
- 숫자가 프로그램 화면과 다르면: 범위(호기 · 기간 · 검색어), 사람선택 반영 여부, 동일 내용 백업
  중복 제거 여부를 먼저 확인하라.

 13. 읽기용 최소 예시 (Python 표준 라이브러리)
------------------------------------------------------------------------------------------
import json, re, zipfile
def nk(s): return re.sub(r"[^a-z0-9]", "", str(s).lower())
records, seen = [], set()
with zipfile.ZipFile("BatchReport_캐시_....zip") as z:
    for f in json.loads(z.read("manifest.json"))["files"]:
        state = json.loads(z.read(f["file"]))
        h8 = f["file"].rsplit("_", 1)[1][:8]
        for name, e in state["entries"].items():
            if (state["machine"], e.get("digest")) in seen:
                continue                                   # 같은 호기 · 같은 내용 백업은 하나만
            seen.add((state["machine"], e.get("digest")))
            meta = {nk(k): v for k, v in e["report"]["metadata"]}
            records.append({"id": f"{h8}:{name}", "machine": state["machine"],
                            "source_folder": state["folder"], "report": e["report"], "meta": meta})
# 이후 3~8장 순서대로 시도 → 묶음 → Lot → 판정 → 기준값 → U 행 → 합산.
