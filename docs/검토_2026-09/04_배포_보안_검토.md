## 1. 동시 접속(멀티유저) 안전성 — 사용자 질문 ①

### 1.1 설계
- **문서 편집(장비IP/특이사항/참고자료/변환계수/양식/취합)**: 1명만 편집, 나머지는
  **읽기 전용**(편집 바인딩 미부착 + 🔒 배너 '누가 언제부터'). 화면 이탈 시 즉시 잠금 반납.
- **읽기 전용 화면(값 확인)**: 잠금 없음.
- **전역 작업 잠금**: 값 업데이트(값취합)·양식 만들기(레시피별)·자동 감시 — 동시에 여러 PC에서
  돌면 장비 배수 접속이 되므로 **단일 실행 강제**(`locking.acquire_global`).
- **접속자 목록/하트비트**: 헤더 '👥 현재 접속', 300초 하트비트로 세션 갱신·만료 정리.
- **단일 인스턴스**(`singleinst`): 한 PC에서 프로그램 2벌 실행 차단(감시 배수 접속 방지).

### 1.2 핵심 한계 — 반드시 이해할 것 🟡
> OneDrive는 **동기화 지연**이 있어 A가 만든 잠금 파일이 B에게 즉시 안 보인다.
> 따라서 이 잠금은 **수학적 상호배제(mutex)가 아니라 "충돌을 크게 줄이는 소프트 락"** 이다.

3중 방어로 보완한다:
1. 획득 직후 재확인(`_verify_owner`) — 동시 획득 일부 검출·양보.
2. **저장 직전 재검증(`check_before_save`)** — 잠금이 새더라도 *남의 저장을 덮어써
   데이터를 잃는 것*만은 막는 **최후 방어선**(파일 stamp 변화·잠금 탈취·충돌본 탐지).
3. OneDrive 충돌본(`파일명-PC이름.xlsx`) 탐지·경고.

### 1.3 잔여 위험과 권고
| 항목 | 판정 | 내용/권고 |
|---|---|---|
| 같은 문서 동시 편집 | 🟡 | 소프트 락 지연 창(수 초). check_before_save가 데이터 손실은 막지만, "나중 저장이 이김"은 발생 가능 → **운영 규칙: 편집은 짧게, 끝나면 닫기** |
| 값취합/감시 동시 실행 | ✅ | 전역 잠금으로 단일화. 앱 재시작 시 자기 잠금 자동 회수(`self` 상태) |
| 크래시 후 유령 잠금 | ✅ | `stale`(30분)·`self`(같은사람·같은PC) 자동 인수 |
| 전원 배포 후 접속 급증 | 🟡 | 하트비트 300초·동일시 미기록으로 쓰기 최소화. 사용자 5~10명 규모 문제없음. **수십 명 규모면 재점검** |

**결론**: 소규모 팀(수 명~십수 명) 동시 사용은 **안전 설계로 대비돼 있다.** 단 잠금은
"동시 편집을 막는 것"이 아니라 "충돌 시 데이터 손실을 막는 것"임을 사용자에게 명확히 안내.

## 2. OneDrive 대량 경로 접근 → 보안메일 재발 여부 — 사용자 질문 ②

### 2.1 과거 사고
2026-08 OneDrive 동기화 폭주로 **'Unusual High-Volume Directory Access'** 경고 수신
(저장폴더 안에 임시파일을 만들 때마다 전원 PC로 동기화된 것이 원인).

### 2.2 현재 대응 (전수 재정비 완료) ✅
- **OneDrive에는 결과물만**(보고서 3의 [OD] 14종). 임시·수집원본·조사산출물·로그는 **전부 로컬**.
- 회차당 저장폴더 신규 파일 **0~1개**(변경 없으면 0개).
- 세션 하트비트 60→**300초**, 만료 5→15분, 내용 동일 시 **미기록**. 잠금도 만료 절반 전 재기록 안 함.
- 무인 취합은 로컬에 먼저 쓰고 **변경 시에만** 저장폴더로 이동.
- `tests/test_onedrive_writes.py`(5) 로 회귀 고정(폴더 지연생성·잠금 재기록 없음·staging 로컬·무변경 시 미생성).

### 2.3 잔여 위험 🟡
| 항목 | 판정 | 내용/권고 |
|---|---|---|
| **초기 배포 시 최초 동기화** | 🟡 | 전원이 exe·과거 양식·취합을 처음 한꺼번에 받으면 일시적 대량 동기화. **권고: 배포를 시간·인원 분산**(한 번에 전원 아님), 또는 IT에 배포 일정 사전 공지 |
| 저장폴더 자체가 큰 팀 공유 | 🟡 | 파일 수가 누적되면 정기 동기화량 증가. **권고: 과거 취합/양식 주기적 아카이브** |
| 새 기능 추가 시 | 🔴(규칙) | **저장폴더에 반복 쓰기를 추가하지 말 것**(회차당 다수/초·분 단위 갱신은 로컬로). 이 규칙이 무너지면 사고 재발 |
| 로컬 폴더가 실수로 OneDrive 안 | 🟡 | `is_under_onedrive` 경고가 있으나 사용자가 무시 가능 → 첫 실행 안내 준수 |

**결론**: **OneDrive '쓰기'로 인한 대량 접근 패턴은 해소됐다.** 단 **최초 배포 순간의
일시적 대량 동기화**는 별개이므로 배포를 분산하고 IT에 사전 공지 권고.

> ⚠ 별개 경보원 — 아래 3·5장의 **장비 `\\IP\c$` 대량 읽기**는 OneDrive와 다른 채널이며,
> EDR/SIEM이 더 민감하게 보는 패턴이다. 함께 관리해야 한다.

## 3. OneDrive의 .exe 다운로드·실행 — 사용자 질문 ③

**현재 계획**: OneDrive 공유 폴더(`프로그램/`)에 .exe를 두고 각자 내려받아 실행.

### 3.1 위험 점검
| # | 항목 | 판정 | 상세 |
|---|---|---|---|
|3-1| **코드 서명 없음** | 🔴 | 미서명 exe → SmartScreen/Defender "알 수 없는 게시자" 경고. 사내 **AppLocker/WDAC(응용프로그램 허용목록)** 환경이면 **차단**될 수 있음 |
|3-2| **PyInstaller onefile → 백신 오탐** | 🟡 | 압축·자기추출 특성상 EDR가 의심. 평판 부족 초기엔 오탐 가능 |
|3-3| **런타임 DLL 추출** | ✅ | `%LOCALAPPDATA%\CamtekAOI\runtime`로 고정(`--runtime-tmpdir`). %TEMP% 미사용 → 백신 격리·세션 임시폴더 사고 회피 |
|3-4| **MOTW(Mark of the Web)** | 🟡 | OneDrive **동기화 클라이언트**로 받은 파일은 대개 Zone.Identifier(인터넷 표식)가 안 붙어 브라우저 다운로드보다 낫다. 그러나 **웹(onedrive.com)에서 직접 다운로드**하면 MOTW가 붙어 SmartScreen 유발 → **동기화 폴더에서 실행 권장** |
|3-5| **Files-On-Demand 미하이드레이션** | 🟡 | 클라우드 전용(구름 아이콘) 상태로 실행하면 exe가 placeholder라 "Failed to load Python DLL"/손상 실행 가능 → **동기화 완료(체크표시) 확인 후 실행** |
|3-6| **OneDrive에서 직접 실행 시 로컬폴더** | 🟡 | 보고서 3-5 참조. `is_under_onedrive` 자동 대체가 작동해야 사고 방지 |
|3-7| **자동 교체 업데이트(실행 중 exe 자기교체)** | ✅ | 백신 행위기반 탐지 대상이라 **[직접 설치] 선택지**(게시 폴더만 열기) 제공. 교체 배치스크립트의 3대 함정(cp949/ping/삭제판정) 회피 |
|3-8| onedir 빌드 오배포 방지 | ✅ | `looks_like_onedir_build` 감지로 게시 차단 |

### 3.2 권고 (우선순위)
1. **🔴 배포 전 IT/보안팀 사전 승인 + 예외 등록 요청**(문서: `docs/IT보안_검토자료.md`의 예외 목록).
   - 실행파일명 `Camtek_AOI_Parameter_manage_v{버전}.exe`
   - 런타임 폴더 `%LOCALAPPDATA%\CamtekAOI\runtime`, 작업 폴더 `%LOCALAPPDATA%\CamtekAOI`
2. **🔴 가능하면 코드 서명**(사내 CA 또는 상용 인증서). AppLocker/WDAC 차단·SmartScreen 경고를
   근본 해소. 미서명이면 최소 **파일 해시(SHA-256)를 함께 공지**해 무결성 확인 경로 제공.
3. **🟡 실행 가이드 명시**: ① 동기화 완료(체크) 확인 → ② **가능하면 로컬로 복사 후 실행**
   (OneDrive 직접 실행 대신) → ③ 최초 실행 경고 시 IT 승인 근거 안내.
4. **🟡 파일럿 배포**: 소수 PC에서 백신/AppLocker 환경 먼저 확인 후 확대.

**결론**: 기술적 취약점(원격코드·통신·지속성)은 없다. 남는 것은 **"미서명 exe + 사내
허용목록/백신 정책"** 이라는 **조직 정책 위험**이다. → 코드 서명 또는 IT 사전 예외등록으로
해소해야 안전 배포 가능.

|4-10| 관리자 권한 요구 | 불필요(사용자 폴더에만 쓰기) | ✅ |

### 4.1 추가로 짚을 점
- **🟡 DLP/데이터 거버넌스**: 저장폴더가 **개인 OneDrive**가 아니라 **회사가 관리하는
  팀/SharePoint OneDrive**인지 확인. AOI 레시피 파라미터는 공정 기밀일 수 있어, 개인
  OneDrive에 두면 DLP 위반·유출 위험. (코드가 아니라 운영 설정 문제.)
- **🟡 장비 접근 계정 권한**: `\\IP\c$` 관리공유 접근에는 장비 로컬 관리자급 계정이 필요.
  이 계정 배포·관리 정책(공용 계정 잠금 위험)을 IT와 합의.
- **✅ 무결성/변조**: 자동 업데이트가 SHA-256으로 다운로드 검증(동기화 덜 끝난 파일 거부).
