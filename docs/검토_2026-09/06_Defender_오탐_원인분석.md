# Windows Defender 트로이 오탐/삭제 — 원인 분석(가설) + 대응

> 증상: 다른 사용자 PC에서 **.exe 로 실행 → 양식 만들기에서 장비 IP(ID·비밀번호
> 정확)로 접속하는 순간** Defender가 트로이(Trojan)로 판정하고 **exe 를 강제 삭제**.
> `run_dev`(소스/파이썬 실행)로는 재현되지 않음. 압축→해제→실행도 걸림.
> 본 문서는 **원인 가설(먼저 파악)** 과 **대응 옵션**을 정리한다(코드 수정 아님).

관측된 우리 코드의 동작(`collector.connect_admin_share`):
```
net use \\{IP}\c$ * /user:{ID} /persistent:no   (비밀번호는 stdin 으로 전달, 명령줄엔 없음)
→ \\{IP}\c$\Job 아래 .ini 등을 로컬로 복사(읽기·복사만)
→ net use \\{IP}\c$ /delete /y
```

---

## 1. 원인 가설 (여러 관점, 가능성 높은 순)

### H1. 행위 기반 탐지 — **관리공유(c$) 접속 + 자격증명 + 파일 복사 체인** (가장 유력)
- **서명 안 된 낯선 exe** 가 `net.exe` 를 띄워 **원격 관리공유 `\\IP\c$` 에 계정으로
  로그인 → 파일을 훑어 복사 → 연결 해제** 하는 동작은, 악성코드(웜/랜섬웨어/측면이동)
  의 **전형적 행위 패턴**과 구별이 안 된다.
- Defender의 **행위 모니터링(Behavior Monitoring) + 클라우드 ML + Block at First Sight**
  가, 평판이 없는 미서명 바이너리에서 이 행위 체인이 관측되면 점수를 올려
  **Trojan 으로 판정하고 즉시 격리·삭제**한다.
- **삭제 시점이 "접속에 성공한 순간"** 인 것이 이 가설을 강하게 뒷받침한다 — 그때
  비로소 관리공유 마운트 + 원격 파일 접근이라는 '악성처럼 보이는' 행위가 완성된다.
- `run_dev` 는 같은 코드지만 **행위 주체가 서명·평판 있는 `python.exe`** 라 이 낯선
  바이너리 기준의 행위 귀속이 다르게 처리돼 안 걸린 것으로 보인다.

### H2. PyInstaller onefile **패킹 ML 오탐** (`Trojan:...!ml`, Wacatac/Sabsik 류)
- PyInstaller onefile exe 는 **자기추출(런타임에 python3xx.dll 을 디스크에 풀고 로드)**
  특성 + 낮은 배포량(prevalence) 때문에 Defender 클라우드 ML 이 자주 **오탐**한다.
  판정명이 대개 `!ml`(머신러닝) 접미사로, **서명 없음 + 저평판**이면 특히 잘 걸린다.
- 단독으로도 삭제될 수 있으나, 본 건은 H1(행위)과 **겹쳐서** '의심 → 악성+격리'로
  넘어갔을 가능성이 높다(판정명이 Trojan 이므로 서명 기반이 아니라 ML/행위일 개연성).

### H3. **압축 전송으로 인한 낮은 평판 + MOTW(Mark of the Web)**
- 파일을 **압축(zip)해 공유 → 해제 → 실행** 했는데, zip 출처(메일/네트워크/다운로드)에
  따라 해제된 exe 에 **인터넷 표식(Zone.Identifier, MOTW)** 이 붙는다. MOTW + 미서명 +
  저평판이면 SmartScreen/Defender 가 **더 공격적으로** 다룬다. → H1/H2 와 합쳐 격리.
- `run_dev` 는 그런 바이너리 아티팩트 자체가 없어 이 경로를 안 탄다.

### H4. **런타임 자기추출 실행** 휴리스틱
- onefile 이 `%LOCALAPPDATA%\CamtekAOI\runtime` 에 DLL 을 쓰고 즉시 로드하는 것
  ("프로세스가 실행파일을 쓰고 그걸 로드")도 휴리스틱 가중치가 붙는다(단독 치명적이진
  않지만 점수에 가산).

### H5. **자격증명을 다루는 프로세스** 자체가 IOC
- 낯선 바이너리가 `net.exe` 에 **비밀번호를 넘겨** 원격 로그온하는 것은 일부 엔진이
  '자격증명 취급'으로 가중한다(우리 코드는 비밀번호를 **명령줄이 아닌 stdin** 으로 넘겨
  최악은 피했지만, 관리공유 로그온 행위 자체는 남는다).

### H6. **조직 정책/ASR 규칙** 개입 가능성
- 그 PC의 Defender 에 **Block at First Sight**, **Tamper/자동 교정**, 또는 **ASR
  (공격 표면 축소) 규칙** — 예: '자격증명 탈취 차단', 'WMI/PSExec 유래 프로세스 생성
  차단', '랜섬웨어 고급 보호' — 이 켜져 있으면, 미서명 프로세스의 관리공유 접근이
  규칙에 걸려 삭제됐을 수 있다. (조직마다 다름 → IT 확인 필요)

> **종합**: 가장 그럴듯한 근인은 **H1(관리공유+자격증명+파일복사 행위 체인) × H2(패킹
> ML 오탐) × H3(미서명·저평판·MOTW)** 의 결합. 특히 "접속 순간 삭제"는 H1 을 가리킨다.

### `run_dev` 가 안전한가? — **보장 아님**
- 같은 코드를 **서명·평판 있는 `python.exe`** 가 실행하니 이 PC에선 안 걸렸을 뿐,
  **행위(net use c$)는 동일**하다. 더 엄격한 정책/ASR 에서는 python.exe 경로도
  걸릴 수 있다. 또한 소스 실행은 각 PC에 Python·의존성 설치가 필요해 배포 목표(단일
  exe·설치 없음)와 어긋난다. → **임시 우회는 되지만 해결책은 아님.**

## 2. 어떻게 하면 Defender 에 안 걸리나 (대응 옵션)

> **결론 먼저**: '마법의 플래그'는 없다. **① 코드 서명(근본) + ② IT 예외 등록(즉효)
> + ③ net use 안 쓰는 접속을 기본으로(행위 트리거 제거) + ④ MS 오탐 신고(현재 빌드
> 임시 해제)** 를 함께 쓰는 것이 정석이다.

### 2-1. 코드 서명 (가장 확실한 근본 대책) ★
- exe 를 **코드 서명 인증서**로 서명하면 '알 수 없는 게시자' 경고와 대부분의 ML 오탐이
  사라지고 SmartScreen 평판이 쌓인다.
- **사내 배포라면**: 회사에 **내부 CA(AD/Intune 로 신뢰 루트 배포)** 가 있으면 그
  **내부 코드서명 인증서**로 서명 → 사내 PC가 신뢰한다(공용 CA 구매 없이 가능,
  가장 현실적). 없으면 공용 CA 의 OV/EV 인증서.
- 서명해도 ML 오탐이 0 이 되는 건 아니지만 발생률이 급감하고, 아래 ②(예외 등록)를
  **게시자(서명) 기준**으로 안정적으로 걸 수 있게 된다.

### 2-2. IT 예외 등록 (가장 빠른 현실 대책) ★
- 보안팀에 요청: Defender **예외(제외)** 를 **서명 게시자 / 파일 해시 / 경로** 기준으로
  등록 + 필요 시 **WDAC/AppLocker 허용 규칙**.
- 파일명이 버전마다 바뀌므로(`..._v4.0.3.exe`), **경로 예외**(게시 폴더 `프로그램\` +
  작업 폴더 `%LOCALAPPDATA%\CamtekAOI`)가 가장 간단. 서명하면 **게시자 예외**가 더 견고.
- 근거 자료로 `docs/IT보안_검토자료.md`(무엇을 하고 안 하는지 정리본)를 제출.

### 2-3. net use 를 안 쓰는 접속을 기본으로 (행위 트리거 제거) ★
- H1(행위 체인)이 근인이므로, **`net.exe` 로 관리공유에 로그인하는 동작 자체를 안 하면**
  '측면 이동처럼 보이는' 패턴이 사라진다.
- 사용자가 **탐색기(Win+R → `\\IP\c$`)로 미리 로그인**해 두고, 프로그램은 그 세션을
  그대로 쓰는 **`net use 접속` 체크 OFF 모드**를 기본으로 안내(이번에 접속 안내창 추가).
- 이 방식은 패킹 오탐(H2)까지 없애진 못하지만 **가장 강한 트리거(H1)를 제거**한다.
- (참고: 무인 자동 감시는 이미 net use 없이 기존 세션 사용이 기본이다.)

### 2-4. Microsoft 오탐 신고 (현재 빌드 임시 해제)
- Microsoft **Defender 오탐 신고(WDSI, "파일 분석 제출")** 에 exe 를 **False Positive**
  로 제출하면 클라우드가 그 **해시**를 몇 시간 내 화이트리스트에 넣어 전 사용자에게 해제.
- 단 **빌드가 바뀌면 해시가 달라져** 다시 신고해야 한다(임시책).

### 2-5. 빌드/패키징으로 오탐률 낮추기 (보조)
- **onefile → onedir**: 런타임 자기추출(DLL 풀기)이 없어 H4 와 패킹 휴리스틱이 준다.
  단 '폴더째' 배포해야 하고, 지금 배포 창은 onedir 게시를 막고 있어 **정책 변경 필요**.
- 이미 적용된 것 유지: `upx=False`, 버전 리소스·아이콘, 최신 PyInstaller.
- 이런 조치는 오탐률을 낮추지만 **미서명 onefile 은 여전히 걸릴 수 있다**(보조책).

## 3. 사용자가 물은 것에 대한 직접 답

- **"압축했다 풀어서 실행했는데 걸렸다 — 압축이 문제인가?"**
  → **압축은 해결책이 아니다.** 해제된 exe 는 **바이트가 동일(같은 해시·같은 휴리스틱)**
  이라 그대로 걸린다. 오히려 zip 출처에 따라 **MOTW 가 붙어 더 나빠질 수** 있다.
- **"build 파일로 프로그램을 직접(로컬에서) 만들면 괜찮나?"**
  → **대체로 여전히 걸린다.** 로컬 빌드 exe 도 **미서명 PyInstaller onefile + 같은
  net use 행위** 라 패킹 ML 오탐·행위 탐지가 동일하게 적용된다. '저평판' 페널티가 조금
  덜할 수는 있어도 신뢰할 수 있는 회피책은 아니다.
- **"run_dev(소스 실행)는 안전한가?"**
  → 이 PC에선 안 걸렸지만 **보장은 아니다**(위 1장 마지막 참조). 배포 대안으로는 부적합.

## 4. 권장 실행 순서 (요약)

1. (즉효) **IT에 예외 등록 요청** — 경로(`프로그램\`, `%LOCALAPPDATA%\CamtekAOI`) +
   가능하면 해시. 근거 = `docs/IT보안_검토자료.md`. + **MS 오탐 신고**로 현재 빌드 해제.
2. (근본) **코드 서명** — 사내 내부 CA 우선. 이후 예외를 **게시자 기준**으로 전환.
3. (트리거 제거) **`net use 접속` OFF(탐색기 사전 연결) 모드를 표준 절차로** 안내·교육
   (이번에 접속 안내창 추가). 필요 시 기본값도 OFF 로 바꾸는 것 검토.
4. (보조) onedir 배포 허용 검토, 빌드 위생 유지.

> 이 네 가지를 함께 적용하면 '미서명 onefile + 관리공유 접속'이라는 **오탐 3대 요인
> (서명·평판·행위)** 을 모두 눌러 재발을 막을 수 있다. 코드 자체에는 악성 요소가 없으며,
> 문제는 **조직 보안 정책 관점의 신뢰(서명/예외)** 다.
