# 보고서 1 — UX 전수조사 (처음 접하는 성인 사용자 기준)

> 대상 버전: `version_v3.0` (Camtek AOI 파라미터 관리, `param_manager`)
> 검토일: 2026-09-03
> 관점: **해당 업무·프로그램을 처음 접하는 성인**이 매뉴얼 없이(또는 매뉴얼만 보고)
> 목표 작업을 끝까지 수행할 수 있는가.

---

## 0. 총평

기능적 완성도와 안정성(오류 코드, 로딩 모달, 되돌리기 안내, 자동 백업, 동시접속 방어)은
사내 도구 치고 매우 높다. 그러나 **"처음 보는 사람이 스스로 이해할 수 있는가"** 기준으로는
**중간 이하**다. 핵심 원인은 세 가지다.

1. **온보딩(첫 사용 안내)이 없다.** 프로그램을 처음 켜면 설명 한 줄 없이
   *"저장 폴더를 지정하라"*는 모달부터 뜬다. "이 프로그램이 무엇을 하는지"를
   화면 어디에서도 알려주지 않는다.
2. **도메인 전문용어가 화면에 그대로 노출된다.** 변형(variant)·설정키·취합·양식·
   MAG·OpticPreset·RTP·Zone/Alg·이탈·Commonality·S/M·Lot·대표 S/M 등. 용어집이
   프로그램 안에 없다. 이 용어를 모르면 버튼 이름만으로는 무엇을 누를지 알 수 없다.
3. **동일 개념이 문서·화면에서 다르게 불린다.** 특히 `docs/사용설명.md`의 앞부분
   (1~7장)은 **폐기된 옛 모델**(공용 파일 / xlsm 가져오기 / 통합 마법사)을 설명하고,
   뒷부분(8장~)은 **현재 탭 모델**을 설명한다. 처음 보는 사람이 위에서부터 읽으면
   화면에 없는 메뉴를 찾게 된다.

아래는 항목별·기능별 전수 결과다. **심각도**는 처음 사용자의 작업 완수를 막는 정도로
매겼다(🔴 막힘 / 🟠 헤맴 / 🟡 사소).

## 1. 첫 실행 · 전역 프레임

| # | 항목 | 현재 동작 | 처음 사용자 관점 문제 | 심각도 |
|---|---|---|---|---|
|1-1| 최초 진입 | 설명 없이 "저장 폴더 확인/지정" 모달 | 프로그램의 목적·다음 할 일을 모른 채 폴더부터 고르라고 함 | 🔴 |
|1-2| "저장 폴더" 개념 | OneDrive 공유 폴더를 지정하는 것이 전제 | "저장 폴더가 무엇을 저장하는 곳인지", "왜 OneDrive여야 하는지" 설명 없음 | 🟠 |
|1-3| "로컬 작업 폴더" 2차 모달 | 저장 폴더 직후 또 다른 폴더 설정 모달 | 폴더를 **두 번** 고르게 됨. 저장 폴더/로컬 폴더 차이를 처음엔 이해 못 함 | 🟠 |
|1-4| 6개 탭 | 파라미터 값 확인 / 양식 만들기 / Commonality 조사 / 특이사항 / 참고자료 / 장비 IP | 탭 순서가 작업 순서와 무관. 처음엔 "어디부터?"를 알 수 없음(값 확인이 첫 탭인데 값이 비어 있음) | 🟠 |
|1-5| 탭 이름 언어 혼용 | 한국어 탭 사이에 영어 "Commonality" | 비전문가에게 "Commonality"는 뜻 불명 | 🟡 |
|1-6| 상단 내비(뒤로/앞으로/처음/크럼) | '값 확인' 탭에서만 표시 | 탭마다 상단 위젯이 나타났다 사라짐 → 일관성 혼란 | 🟡 |
|1-7| 상태바 | 안내/경고 + ✕ 닫기, warn=빨강 | **좋은 설계.** 경고가 화면에 계속 남지 않음 | ✅ |
|1-8| 매 실행 "저장 폴더 그대로 쓸까요?" 모달 | 켤 때마다 확인 | 폴더가 안 바뀌는 게 보통인데 매번 물어봄 → 반복 클릭 피로 | 🟡 |

**개선 제안**
- 첫 실행 시 **환영/개요 화면 1장**: "이 프로그램은 AOI 장비의 레시피 파라미터를
  호기별로 읽어 비교·관리합니다. 순서: ① 장비 IP 등록 → ② 양식 만들기 → ③ 값 업데이트
  → ④ 값 확인." 3~4줄이면 충분.
- 저장/로컬 폴더 2단 설정을 **1개 마법사 단계**로 묶고, 각 폴더가 무엇을 담는지 그림 1장.
- 매 실행 폴더 확인 모달은 **상태바 한 줄 + '폴더 변경' 버튼**으로 대체(무마찰 시작).
- 탭에 번호/순서 힌트(①②③) 또는 첫 탭을 "시작하기"로.

## 2. 파라미터 값 확인 탭 (기본 진입 화면)

| # | 항목 | 처음 사용자 관점 문제 | 심각도 |
|---|---|---|---|
|2-1| 호기 격자(S0) | "호기"라는 단어는 통용되나, 격자만 보이고 다음에 뭘 하는지 안내 약함 | 🟡 |
|2-2| 최초엔 값이 비어 있음 | 첫 탭인데 "값 확인"할 값이 아직 없음(양식·업데이트 선행 필요). 처음 사용자는 "고장인가?"로 오해 | 🟠 |
|2-3| 액션바: 값 업데이트 / 이력 확인 / 최신 취합 새로고침 / ⋯파일 | "값 확인" 화면에 "값 업데이트"가 섞여 있어 읽기/쓰기 경계가 흐림 | 🟠 |
|2-4| 제목 "AOI-25 : PI3 · 변환계수 …" | 변환계수 수치가 그대로 노출 — 뜻을 모르면 노이즈 | 🟡 |
|2-5| 호기 우클릭=삭제, 카드 우클릭=레시피 삭제 | 숨은 우클릭 메뉴 — 처음엔 발견 불가(discoverability 낮음) | 🟠 |
|2-6| 이탈/과반수 색칠, fail=노랑 등 색 규칙 | 범례가 화면에 상시 표시되지 않음 → 색의 의미 추측 | 🟠 |

**개선 제안**
- 값이 비었을 때 **빈 상태 안내(empty state)**: "아직 취합된 값이 없습니다. [양식 만들기]에서
  양식을 만든 뒤 [값 업데이트]를 실행하세요." + 바로가기 버튼.
- 읽기 전용 화면과 쓰기 동작(값 업데이트)을 시각적으로 구분(색/구분선/아이콘).
- 색 규칙 **범례를 화면에 상시 노출**하거나 셀 hover 시 툴팁.
- 우클릭 전용 기능은 눈에 보이는 버튼/⋯메뉴로도 접근 가능하게.

## 3. 양식 만들기 탭

이 탭이 **가장 학습 곡선이 가파르다.** 처음 사용자가 스스로 완수하기 가장 어려운 구간.

| # | 항목 | 처음 사용자 관점 문제 | 심각도 |
|---|---|---|---|
|3-1| "양식"이라는 개념 | "양식(폼)"이 "어떤 파라미터를 관리 대상에 넣을지 고른 목록"이라는 뜻인데, 그 정의가 화면에 없음 | 🔴 |
|3-2| 레시피(PI2/3/4·RDL1~4·기타 직접입력) | 레시피/변형(variant) 계층 개념을 모르면 선택 불가 | 🟠 |
|3-3| 장비/로컬에서 신규 → **실제 Excel로 열림 → 편집 → [편집 완료]** | 프로그램 안에서 하다가 **외부 Excel로 튕겨 나가** 편집하고 다시 돌아오는 흐름은 매우 이례적. 처음엔 "왜 엑셀이 떴지?", "돌아오려면?" 혼란 | 🔴 |
|3-4| '사용' 열 / '최종 Parameter' 열 편집 | 무엇을 체크해야 하는지 판단 기준(도메인 지식) 필요 | 🟠 |
|3-5| 변형별 계수 확정창(`_ask_scales`) | LINEAR/AREA/RAW 변환방식·계수 신뢰도 — **엔지니어 전용 판단**. 처음 사용자는 근거 없이 확정하게 됨 | 🔴 |
|3-6| 기존 양식 수정: "무엇을 기준으로 열지"(저장된 원본/장비 다시 읽기/로컬 다시 읽기/확정본만) | 선택지 4개의 차이를 이해하려면 "스냅샷 vs 최신 파서" 개념 필요 | 🟠 |
|3-7| ✔ 항목 추가 가능 / ⚠ 원본 없음 배지 | 배지 뜻이 즉시 이해되지 않음(원본=무엇의 원본?) | 🟡 |
|3-8| 🗑 레시피 삭제 | **되돌리기 안내를 삭제 전·후 양쪽에 표시, 이름 직접 입력 확인** — 매우 안전한 설계 | ✅ |

**개선 제안**
- 탭 최상단에 **"양식이란?" 1줄 정의 + 3단계 흐름 배너**.
- Excel 왕복 편집은 처음 사용자에게 큰 벽이다. **화면 편집기(tksheet)를 기본**으로,
  "엑셀에서 편집"은 고급 옵션으로 내리는 것을 검토(현재도 화면 편집기 존재).
  최소한 Excel이 열릴 때 **"엑셀에서 편집 후 저장하고 닫으면 자동으로 여기로 돌아옵니다"**를
  큰 안내로.
- 계수 확정창에 **추천값을 기본 채택**할 수 있는 "추천값 그대로 쓰기(권장)" 버튼과
  "계수가 무엇인지" 도움말 링크. 처음 사용자가 근거 없이 숫자를 고르지 않게.

## 4. Commonality 조사 탭

| # | 항목 | 처음 사용자 관점 문제 | 심각도 |
|---|---|---|---|
|4-1| 탭 자체 | 영어 명칭 + 고급 분석 기능. 일반 담당자가 언제 쓰는지 불명 | 🟠 |
|4-2| S/M · Lot · 슬롯(웨이퍼) · 디바이스 · 공정번호 · Zone그룹 · 이탈 | 반도체 검사 도메인 용어 밀집. 비전문가 진입 불가 | 🔴 |
|4-3| Lot 계획 엑셀 업로드 → 호기 필터 → 폴더 실재 확인 → 안전복사 → 양식 → 값 조사 → 비교 → 뷰어 | **7단계** 파이프라인. 각 단계 사전지식 요구, 진행 위치 표시 약함 | 🟠 |
|4-4| 자동 감시 배너(🔔) | "감시"가 무엇을·어떻게 감시하는지 배너만으로는 불명 | 🟡 |
|4-5| 폴더 매칭 3단계/토큰 겹침, 대표 S/M, min_match 색표시 | 내부 로직이 UI 라벨로 새어 나옴 | 🟡 |

**개선 제안**
- Commonality는 **명백히 전문가용**이다. 처음 사용자를 위한 개선보다는,
  "이 탭은 여러 Lot의 파라미터 공통성/변경을 조사하는 고급 기능입니다"라는
  **역할 안내 + 대표 시나리오 1개**를 배너로.
- 한국어 병기: 탭 이름 "공통성(Commonality) 조사".

## 6. 값 업데이트 · 자동 감시(공통 흐름)

| # | 항목 | 처음 사용자 관점 문제 | 심각도 |
|---|---|---|---|
|6-1| 값 업데이트: 레시피 선택 → IP↔호기 매칭 → 하위 레시피 이름 매칭 → 취합 | **연속 모달 3~4개**. 각 창이 결정을 요구하나 "몇 단계 중 몇 번째"인지 안 보임 | 🟠 |
|6-2| net use vs 기존 연결 · 장비별 ID/PW | 처음 사용자에게 SMB/자격증명 개념 부담. 잘못 고르면 접속 실패 | 🟠 |
|6-3| "불일치" 표기 후 계속 진행 여부 질문 | 불일치가 무엇을 뜻하는지, 계속해도 되는지 판단 어려움 | 🟠 |
|6-4| 자동 감시 설정창(ON/OFF·주기·시간대·장비별 레시피·폴더 지정 필수·접속방식) | 정보량이 매우 많은 단일 창. 처음엔 압도됨. 단 콤보 아래 "지금 설정의 뜻" 1줄 설명은 **좋음** | 🟠/✅ |
|6-5| 로딩 모달 + 백그라운드 | 멈춘 것처럼 안 보이게 처리 — **좋음** | ✅ |

**개선 제안**
- 다단계 모달에 **"단계 N/M" 표시**와 각 단계 1줄 목적 설명.
- "기존 연결 사용(권장)"을 기본 선택으로 두고 net use는 접어두기(현재도 권장 표기 있음 → 시각적 강조 강화).

## 7. 처음 사용자 "첫 성공까지" 시뮬레이션 (매뉴얼 없이)

가장 흔한 목표 = *"장비 몇 대의 PI3 값을 비교해 보고 싶다"*.

1. 프로그램 실행 → 저장 폴더 지정(무엇인지 모름) → 로컬 폴더 지정(또 폴더?) — **여기서 이미 이탈 가능**
2. 첫 화면 '값 확인' — 비어 있음 → "고장?" 오해
3. '양식 만들기'로 가야 함을 **스스로 알아내야 함**(안내 없음)
4. 레시피 선택 → 장비 수집(IP/접속?) → **Excel이 튀어나옴** → 편집 후 돌아오기 → 계수 확정(근거 모름)
5. '값 업데이트' → 3~4개 모달 통과 → 취합 생성
6. '값 확인'에서 비로소 값 확인

**결론**: 각 단계가 개별적으로는 안전하게 설계돼 있으나, **단계 사이를 잇는 안내가 없어**
처음 사용자는 3·4단계에서 대부분 막힌다. 매뉴얼(사용설명.md)에 의존하는데, 그 매뉴얼조차
앞부분이 구버전이라 신뢰도가 낮다.
