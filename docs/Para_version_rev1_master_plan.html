0. 문서 목적과 현재 상태

이 문서는 다음 AI 세션에서 계획을 다시 설명하지 않고 작업을 시작하기 위한 기준이다. 계획에 기재된 기능을 구현 완료로 간주하지 않는다. 구현 시 원격 브랜치 최신 코드와 실제 테스트 결과를 먼저 확인한다.

claude/ux-bento-navy-lime의 확정 커밋을 복사해 version_rev1에서 수행한다. 원본 브랜치에 웹 UI 전환 코드를 반영하지 않는다.

계획 B · 배치 분석 확장

첨부 사양서의 11개 지표

claude/ux-bento-navy-lime에서 기존 tkinter 환경을 유지해 개발한다. 헤드리스 분석 엔진을 먼저 완성해 이후 웹 UI에서 재사용한다.

입력 문서: 배치리포트분석_사양서(1).html. 이전 첨부와 파일 내용이 동일함을 확인했다. 첨부 사양서는 배치 분석 요구사항의 기준이며, 이 문서는 전환 계획·브랜치 경계·구현 전 확인 사항을 보완한다.

과거 코드 검토 기준: b235ec2402888fb3356292aafe55e895f021b5e8. 이 SHA는 최신 상태를 보증하지 않으며 분기 기준으로 자동 사용하지 않는다. WebView2는 사용자 확인상 문제가 없어 보이는 상태일 뿐, 새 앱 실기 검증·조직 승인 완료를 뜻하지 않는다.

브랜치·순서A. UI 개편보안B. 배치 분석미확정 정의검증다음 AI 지시

1. 브랜치 운영과 권장 순서

권장 순서: 배치 분석 확장(B) 구현·검증 → 원본 UX 브랜치 확정 SHA 기록 → 그 커밋에서 version_rev1 생성 → 웹 UI 개편(A). 이 순서는 권장안이며 이번 문서 작성으로 브랜치를 생성하거나 소스를 변경하지 않는다.
대상허용 작업금지/주의
claude/ux-bento-navy-lime첨부 사양서에 따른 배치 분석 엔진·tkinter UI·출력·테스트·인수인계Tauri 전환 코드를 섞지 않음
version_rev1확정된 원본 커밋 복사 후 Tauri/React 전환, 라이선스·빌드·UI 회귀 검증원본 브랜치로 역병합·운영 자동 배포 금지
version_new / version_v7.0 / 기타필요시 읽기 비교수정·push·자동 병합 금지
  1. 작업 시작 시 원격 HEAD, 작업 트리 변경, AGENTS.md·CLAUDE.md·AI_HANDOFF를 확인한다.
  2. 기존 문서의 version_new 고정 규칙은 사용자 최신 지시에 맞춰 작업별로 정정한다. ai_sync 도구의 대상 브랜치도 확인한다.
  3. version_rev1이 이미 있으면 초기화하거나 덮어쓰지 않고 분기점·차이를 확인한다.
  4. 먼저 복사해야 할 경우 복사 SHA를 기록하고, 이후 B의 검증된 커밋만 명시적으로 통합·재검증한다. 원본 전체 자동 병합은 하지 않는다.
  5. 동일 브랜치를 Claude와 ChatGPT가 동시에 수정하지 않는다. 커밋·문서로 순차 인수인계한다.

3. 계획 A — 구조·성능·의존성

React/TypeScript → Tauri 제한 명령 → Python 작업 계층 → 기존 분석·파일 처리. UI가 UNC 파일을 직접 읽지 않으며, Python 엔진이 허용된 읽기·저장을 수행한다.

  • Python sidecar는 표준입출력 기반 IPC를 우선 사용한다. 요청 ID·프로토콜 버전·진행·오류·완료·취소를 정의하고 표준출력은 프로토콜 전용, 로그는 별도 로컬 경로로 분리한다.
  • 임의 Python 코드·셸 문자열·임의 프로그램 실행 API를 노출하지 않는다. UI와 Python 양쪽에서 요청·경로·크기 제한을 검사한다.
  • UI에서는 표 행·열 가상화, 입력 지연 처리, 부분 갱신, 결과 분할 조회를 적용한다. Python의 긴 작업은 화면 처리를 막지 않게 분리한다.
  • 취소는 안전한 중단점에서 처리한다. 공유 저장·업데이트 교체 도중 강제 종료하지 않는다. 중복 실행과 고아 프로세스를 테스트한다.
  • 헤드리스 엔진에는 tkinter/React 의존성을 넣지 않는다. 기존 파서·WPH·Commonality·Excel 출력을 가능한 그대로 재사용한다.
  • Node·Rust는 개발/빌드 도구이며 사용자에게 별도 설치를 요구하지 않는 구성을 목표로 한다. WebView2와 패키징된 Python은 별도 배포 검증 대상이다.
Tauri 도입만으로 속도 개선을 보장하지 않는다. 기존 약 1만 줄 equip_app의 전체 화면 재생성, WPH 셀별 위젯 생성, 메인 콜백의 집계·저장이 우선 개선 후보다. 개선율이나 디자인 점수를 근거 없이 약속하지 않는다.

패키지 선정 원칙

Tauri·React 등 후보의 사용료와 최종 제품 전체의 배포 조건은 별개다. 정확한 버전 기준 직접·간접 의존성과 개발 도구 라이선스, 취약점, 고지문·SBOM을 확인한다. 유료 Enterprise 기능·체험판·상업 제한 자산은 사전 합의 없이 사용하지 않는다. Anaconda 배포판·저장소는 사용하지 않는다. 표·그래프 라이브러리는 아직 확정하지 않았다.

5. 계획 A — 호환성과 배포

  • 프로그램명 Camtek_AOI_manager, 기존 설정 키·경로·Excel 양식·파라미터 색상·최근 조사 설정을 우선 보존한다.
  • 변경이 필요한 데이터에는 schema_version, 백업, 구버전 읽기·쓰기 영향과 복구 절차를 둔다. UI 전환을 이유로 공유 파일을 일괄 변환하지 않는다.
  • 현재 단일 exe 교체를 새 구성에 그대로 적용하지 않는다. 설치 패키지 또는 버전별 폴더 교체를 시험 빌드 후 선정한다.
  • 화면·Python·리소스의 버전을 묶어 검증하고 다운로드 완료 후 전환한다. 중단 시 직전 전체 구성을 복구한다.
  • 해시는 손상 검증이며 게시자 인증과 다르다. 배포 권한·업데이트 서명·Windows 코드서명 검토를 분리한다. 개인키를 소스·OneDrive에 넣지 않는다.
  • 기존 앱에서 새 패키지로 넘어가는 최초 전환 절차가 필요하다. 운영 배포폴더 수정과 게시에는 별도 지시가 필요하다.

6. 계획 B — 첨부 사양서 기반 배치 분석

작업 브랜치: claude/ux-bento-navy-lime. 기존 tkinter/tksheet와 openpyxl을 유지한다. pandas·numpy·bs4·matplotlib 등 새 런타임 패키지를 추가하지 않는다. Batch는 Report 1개이며 Lot으로 치환하지 않는다.

사용 흐름

  1. “WPH 조사” 탭을 “배치 리포트 분석”으로 확장한다.
  2. 호기·Report 폴더·검색어/기간·파일 목록을 선택한다. 마지막 실제 조사 설정만 복원하는 동작을 유지한다.
  3. 시작 직전 11개 지표를 한 목록에서 선택한다. 기본 전체 선택. 유효 매수 옵션은 WPH에 적용하고 다른 지표를 일괄 제외하지 않는다.
  4. 증분 수집·1회 파싱 → 선택 지표와 필요한 선행 통계 계산 → 미리보기.
  5. 결과 제목과 포함 지표를 선택하여 로컬 HTML·Excel로 출력한다. 미리보기와 출력은 같은 계산 결과를 사용한다.
  6. 고정 경로 가동률 대시보드를 열고 앱에서 수동/일일 갱신한다.

복수 상태는 복수 유형에 포함될 수 있어 유형별 배치 수 합은 이슈 배치 수를 초과할 수 있다. 정상·이슈·확인불가 집계와 중복 규칙을 표마다 표시한다. 첨부 예시 외 오류도 미분류 목록에 남긴다.

7. 계획 B — 데이터·증분·출력 설계

기존 코드 재사용

첨부 문서가 지정한 wph.parse_report, parse_batch_datetime, hms_to_seconds, parse_filename_datetime, list_reports, wph_status.classify, wph_html, localdirs를 최신 소스에서 검증 후 재사용한다. raw metadata와 wafer 전체 컬럼·순서를 보존한다. 기존 investigate 반환 tuple을 무조건 변경하지 말고 새 API/옵션/어댑터로 기존 호출자를 보호한다.

데이터 모델

Batch: source identity·호기·파일명·시작/종료·Batch초·완료 wafer수·표 행수·die/yield·Job/Setup·Job recipe·상태.
Wafer: batch identity·원본 순서·Lot·Wafer ID·Faults·die/yield·Pass/Fail 원문·Recipe(s)·표준 유형들·성격·중단 추정.
Job recipe와 wafer Recipe(s)는 다른 의미이므로 별도 필드로 유지한다. 각 계산 결과에 제외 사유·표본 수·분류/수식 버전을 포함한다.

증분 저장

  • 로컬 상태 JSON + 호기별 batches/wafers JSONL을 기본으로 하며, 필요시 호기·연월로 분할한다.
  • 파일명 날짜로 후보를 좁히되, high-watermark만으로 늦게 도착한 과거 파일·날짜 없는 파일을 영구 누락하지 않게 보완한다.
  • seen 판단 범위는 호기·수집원·파일 식별자를 고려한다. 백업의 동일 내용은 중복 제거하고, 동명 다른 내용은 충돌로 표시한다.
  • 읽기·파싱 실패는 성공 처리하지 않는다. 재시도 목록을 유지하고 성공한 저장 이후에만 상태를 갱신한다.
  • 두 JSONL과 상태 사이의 중단·부분 저장을 복구하도록 세대/커밋 표시 또는 저널을 설계한다. 미완성 배치가 통계에 들어가지 않게 한다.
  • 원문 상태를 보존해 분류 사전 변경 시 원본 재접근 없이 재분류한다. 무한 전체 재계산 비용은 단계별 성능 측정 후 로컬 집계 캐시로 개선한다.
  • 수동·자동 조사는 같은 작업 잠금으로 중복 실행을 막는다. 검색 조건 변경과 폴더 변경을 상태 키에 반영한다.

출력과 준실시간 대시보드

  • 기존 WPH Excel·HTML 유지 + 신규 분석 HTML·Excel + 고정 경로 가동률 대시보드.
  • 분석 Excel: Batches / Wafers / 유형별빈도 / Recipe별defect / 조치시간 / 가동률. 선택하지 않은 지표의 처리 방식은 일관되게 표시한다.
  • HTML은 CSS·SVG·필요한 토글 JS를 내장한 단일 파일. 표·차트 제목, 축 단위, 날짜 눈금, 원문 Report 추적, 출력 인쇄 스타일 제공.
  • 대시보드 경로: CamtekAOI/배치분석/대시보드/가동률_대시보드.html. 실제 경로는 localdirs 구현을 따른다.
  • 파일 새로고침 예시 30분은 표시 갱신일 뿐 장비 수집이 아니다. 일/주/월 토글은 내장 집계만 전환한다.
  • 데이터 갱신은 앱의 [지금 업데이트] 또는 하루 1회 자동 조사만 수행한다. 자동 조사는 모달을 띄우지 않고 앱 실행 중에만 작동한다. 앱 종료 중에는 갱신되지 않음을 표시한다.
  • 웹 UI 전환 후 앱 내부는 IPC로 진행/결과를 갱신할 수 있지만, 외부 브라우저의 단일 HTML은 계속 독립 오프라인 파일로 유지한다.

11. 다음 AI가 읽고 시작할 절차

  1. 사용자가 요청한 작업이 A(웹 UI)인지 B(배치 분석)인지 먼저 확인한다. 이 문서만으로 양쪽 브랜치를 동시에 수정하지 않는다.
  2. 해당 브랜치 최신 HEAD와 변경 사항을 읽는다. 첨부 사양서와 본 문서의 요구사항을 실제 코드에 대응시켜 이미 완료된 작업을 중복 구현하지 않는다.
  3. 작업 시작 SHA·범위·보존할 규칙·확인 필요한 계산 정의·테스트 계획을 기록한다.
  4. 작은 검증 가능한 단계로 구현한다. 계약/API가 바뀌면 호출자·구버전·취소·실패 경로를 함께 검증한다.
  5. 요청된 브랜치에만 커밋·push하고 SHA, 변경 파일, 테스트 결과, 미완료, 빌드·배포 여부를 인수인계한다. 강제 push/reset·자동 PR 금지.
