# 배치 리포트 분석 구현 · 2026-09-20

## 범위와 시작점

사용자 지정 브랜치 `claude/ux-bento-navy-lime`, 시작 커밋
`b235ec2402888fb3356292aafe55e895f021b5e8`의
`docs/배치리포트분석_사양서.html`을 기준으로 구현했다.
이번 작업은 배치 분석 확장만이다. tkinter와 기존 테마, 실행파일 버전,
장비 파라미터 수정/취합, OneDrive 업데이트 체계는 유지한다.
Tauri/React 전환, `version_rev1` 분기, 다른 브랜치 변경은 하지 않는다.

## 사용 흐름

1. **배치 리포트 분석** 탭에서 조사할 호기와 기존 Report 폴더를 지정한다.
2. 검색어 또는 기간을 선택한다. 기간은 기존처럼 파일명 날짜 기준이다.
   날짜 없는 이름은 기간 검색에 포함되지 않으며, 검색어 모드 전체 조사로 수집할 수 있다.
3. 필요하면 **추가 Report 폴더**에서 호기별 백업 폴더를 추가한다.
4. **조사 시작** → M01~M11 지표 선택(최초 기본 전체).
   유효 Lot 매수는 WPH에만 적용한다. 품질 후보 기준도 이 창에서 수정한다.
5. 완료창에서 분석 HTML, 분석 Excel, 결과 폴더, 대시보드를 연다.
   WPH 선택 시 종전 WPH Excel/HTML도 생성하고 기존 HTML 구성창도 사용할 수 있다.
6. **지금 업데이트**는 마지막 실행 조건의 snapshot을 재사용한다.
   **하루 1회 자동**은 기본 OFF, 앱 실행 중만 작동하며 실패 시 기존 watcher backoff를 따른다.
   앱 종료 중의 예약 실행이나 HTML만 열어 둔 상태의 원본 수집은 하지 않는다.

모든 파일을 선택한 검색 결과는 다음 조사에 새 파일도 포함한다.
일부만 선택하면 해당 파일명 목록을 유지한다. 새 검색을 하면 전체 선택으로 재설정된다.
검색어/기간을 바꾸면 이전 검색에서의 일부 파일 선택을 새 조건에 적용하지 않는다.
마지막 실행 설정 한 개만 저장하고 이전 조사 이력을 화면 선택에 합치지 않는다.

## 계산 규칙

|지표|기준|
|---|---|
|M01 WPH|유효 매수와 일치하고 Batch Time > 0. 합산 WPH와 Report별 WPH 산술평균 구분. 전체/호기/호기×Job Recipe|
|M02 스캔 가동률|호기×일/ISO주/월. Batch Start 버킷에 전체 Batch Time 귀속. 달력시간 대비 비율과 첫 시작~마지막 종료 밀도 병기. 진행 중 주·월은 마지막 데이터 시각까지 부분 관측창|
|M03 오류 빈도|전체/호기/호기×Job Recipe. Wafer 발생 수와 중복 제거 Report 수 구분. 원문/Report/wafer 상세 보존|
|M04 오류 성격|예방형/조치형/중단/결과형/미확인. 사전 버전 1. 원인 확정 아님|
|M05 Aborted|원본 행 순서상 첫 이슈(첫 Aborted 포함)는 직접, 그 이후 Aborted는 연쇄 추정. Skipped/빈 상태는 트리거 제외. 원본 수=직접+연쇄|
|M06 재시작 간격|같은 호기와 전체 Job/Setup의 바로 다음 배치 시작−이슈 배치 종료. 0~1440분만 유효. 역전/누락/다음 없음/24h 초과를 제외 사유로 표시|
|M07 baseline|M06 유효 간격 전체의 평균/중앙/최대. 실제 조치시간 아닌 proxy|
|M08 정상 defect|Pass wafer만 Wafer Recipe(s)별 Bad Dice 평균/중앙/P95/최대. P95는 Excel PERCENTILE.INC와 같은 선형 보간|
|M09 이상 후보|같은 Wafer Recipe(s)의 **이전 Batch End** 정상 표본으로 평가. 기본 최소 20개, Bad Dice > 과거 P95 또는 Yield < 과거 중앙−5 percentage points. 최소 표본/수율 하락은 변경 가능. 같은 종료시각끼리 기준을 공유하지 않음|
|M10 완주율|Wafers Scanned / wafer 행 수. 0/부분/100%/확인 불가. 음수·행수 초과·분모 없음은 확인 불가|
|M11 미분류|기존 분류 외 원문은 Unclassified로 남기며 Report/wafer를 표시. 빈 상태도 확인 불가로 보존|

사양서에서 구체적 수치가 정해지지 않은 M09는 조사 창에 **검토용 기본값**을 노출했다.
자동 Hold 또는 장비 쓰기를 하지 않는다. 모든 집계는 현재 선택 자료 범위이며
품질/가동률/복구 수치를 실제 원인·OEE·인증 임계치로 해석하면 안 된다.
100% 초과 가동률과 음수 유휴 추정값은 숨기거나 0~100으로 잘라내지 않는다.
스캔 gap은 호기별 이전까지의 최대 종료시각으로 계산하여 중첩 배치도 식별한다.

## 파일 · 안전성 · 사양서에서 보완한 점

- 기존 `localdirs` 루트 아래 `배치분석/조사_시각/`에 분석 HTML/XLSX,
  호기별 취합 텍스트, 조사설정 JSON을 저장한다. M01 선택 시 WPH Excel/HTML 추가.
- `배치분석/대시보드/가동률_대시보드.html`은 고정 경로에 원자적으로 교체한다.
  M02를 선택한 조사만 대시보드를 갱신한다. 페이지에 데이터 생성 시각을 표시한다.
- `배치분석/누적/{호기+원본폴더의 SHA256}.json`에 원본 파싱 결과와 파일 signature를
  **한 트랜잭션**으로 저장한다. 분리된 batches/wafers JSONL 대신 단일 JSON을 쓴다.
  전원 종료 시 상태만 기록되거나 Wafer 자료만 빠지는 불일치를 피하기 위한 변경이다.
- 원본은 읽기만 한다. 접속은 기존 Windows 탐색기 세션. 자격증명/포트 연결/HTTP 서버/
  외부 통신/추가 패키지가 없다. 호기는 순차 처리하며 사이에 기존 정책과 같은 2초 간격.
- 출력 루트는 UNC/Windows 네트워크 드라이브/OneDrive/원본과 겹치는 위치를 거부한다.
  로컬 cache와 결과만 쓰며 공유 원본 쓰기/추가 OneDrive 동기화를 하지 않는다.
- 마지막 날짜만으로 탐색을 자르지 않는다. 조건에 맞는 파일 이름·수정시각·크기를 확인해
  새 파일/변경 파일만 기존 HTML 파서로 한 번 읽는다. 늦게 도착한 과거 Report도 수집한다.
  내용이 바뀌어도 크기와 수정시각을 **동일하게 강제 보존**한 파일은 변경 감지가 불가능하다.
- 읽기 전후 signature가 바뀌면 제외하고 다음 조사에서 재시도한다. 완료 Batch End와
  Wafer 표가 없으면 파싱 실패로 처리하며 성공 캐시에 넣지 않는다.
- 원본에서 사라진 파일은 누적 자료로 유지하지만 **현재 검색어/기간/선택 파일**에
  맞는 자료만 집계한다. 연결 불가 시 캐시 사용을 오류·캐시 전용 수로 명시한다.
- 같은 호기의 동일 파싱 내용 백업은 하나만 집계한다. 같은 이름/다른 내용은 둘 다 남기고
  알림을 표시한다. Excel Batches/Wafers의 원본 폴더 열로 구분한다.
- 캐시 손상·알 수 없는 스키마는 자동 덮어쓰지 않고 실패한다. 잠금/원자 교체 실패 시
  이전 캐시는 유지한다. 완성되지 않은 산출물은 `.진행중_` 폴더에서만 만들고 실패 시 제거한다.
- 앱 내부 mutex와 자동 수집 busy 상태로 회차 겹침을 막는다. 여러 PC 사이의 새로운 공유
  잠금은 만들지 않으므로 동일 장비에 대한 이 기능의 자동 갱신은 한 PC에서 운영한다.
- HTML은 원문을 escape하고 Excel은 원문 문자열을 formula가 아닌 text로 저장한다.
  HTML은 CSS/SVG/기간 토글을 모두 내장한다. 1800초 새로고침은 파일 재열기만 한다.

  손상 cache, 경로 거부, 선택/기간/오프라인 cache, Excel 실제 chart XML/원문 보안,
  HTML 기간 토글, 하루 1회와 busy 제어.
- 전체 독립 테스트: `python tools/check_project.py` (기존 원본 .xlsm 의존 engine 테스트 제외).
- 이 개발 환경의 합성 419 batch / 10,475 wafer에서 전체 지표+HTML/Excel 생성 7.51초,
  변경 없는 재수집만 0.12초(파싱 0, 재사용 419)였다. 실제 SMB/Windows 속도 보장 수치가 아니다.
- **실제 419건/9558 wafer 샘플은 제공되지 않아 사양서의 정답값 재현 미검증.**
- Windows tkinter 레이아웃/DPI, Excel 실제 화면, 사내 SMB/EDR, 대용량 실제 데이터,
  OneDrive 운영 환경, exe 빌드·배포는 별도 실기 확인이 필요하다.
- 소스 push로 기존 exe가 바뀌지 않는다. 검증 후 기존 `build_exe.bat <신규버전>`과
  앱의 개발자 배포 절차를 사용한다. 이번 작업에서 버전 변경/빌드/게시하지 않는다.
