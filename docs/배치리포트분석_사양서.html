배치 리포트 분석 — 구현 사양서 (인수인계용)

이 문서 하나로 다른 작업자(또는 다른 AI 세션)가 Para(Camtek AOI 파라미터 관리 프로그램)의 기존 “WPH 조사” 기능을 “배치 리포트 분석”으로 확장 구현할 수 있도록 작성했다. 목적 → 제약 → 입력 → 재사용 코드 → 지표 → 가동률/실시간 창 → 증분 수집 → GUI → 출력 → 단계 순.
용어: 결과물 표기는 사용자 확정에 따라 장비 원본 용어인 “Batch(배치)”를 그대로 쓴다(“Lot”로 치환하지 않는다). 배치 1회 = 여러 wafer를 한 번에 스캔한 단위 = batch report(HTML) 1개.

0. 배경 — 왜 확장하나

  • AOI(자동 광학 검사) 장비가 스캔마다 batch report(BatchReport.htm)를 자동 생성한다. 수백~수천 개가 흩어져 있어 수작업 집계가 불가능하다.
  • 현재 Para의 WPH 조사는 처리량(Wafers Per Hour)과 에러 상태 요약만 낸다. 자동화 추진(무인화 STEP 1: 현황 분석)에 필요한 에러 원인·조치시간·임계치·가동률 지표가 없다.
  • 특히 에러 상당수가 원인 기록 없이 “Aborted”로만 남아, 단순 집계하면 문제 규모가 크게 왜곡된다(작업자 중단 → 이후 대기 wafer가 전부 Aborted).
  • 따라서 기존 WPH 조사를 배치 리포트 분석으로 확장해 처리량·에러·가동률을 한 번의 조사로 함께 산출한다.

1. 목표 (이 확장이 해내야 할 것)

  • 한 번의 조사 → 두 갈래 결과: 파싱은 1회, 결과는 ① WPH 처리량(기존 유지) + ② 배치 리포트 분석(신규)로 낸다.
  • 조사 시작 시 “지표 선택창”을 띄워 아래 통합 지표 카탈로그에서 계산·출력할 지표를 사람이 고른다(기본 전부 체크).
  • 아래 지표를 자동 계산한다(처리량·가동률·에러 유형/성격/왜곡보정·조치시간·복구 baseline·Recipe defect 임계치·Yield 급변·완주율·미분류 포착).
  • 결과를 ① 오프라인 단일 .html(인라인 SVG 그래프) + ② .xlsx로 출력한다.
  • 가동률 실시간(준실시간) 상태 창: 브라우저로 여는 대시보드 .html. 하루 1회 자동 또는 [지금 업데이트] 버튼으로 갱신.
  • 증분 수집: 최초 1회만 전체, 이후엔 마지막 저장 날짜 이후 리포트만 파싱해 빠르게 갱신(중복 조사 방지).
  • 새 에러가 나와도 누락 없이 “미분류(Unclassified)”로 자동 포착한다.

2. 반드시 지킬 제약 (Para 공통 규칙)

이 제약을 어기면 안 된다. 사양서 원본(AOI Lot Report 분석)은 pandas·beautifulsoup4를 쓰지만, Para에서는 금지다. Para는 이미 stdlib로 batch report를 파싱하고 있으므로 그대로 순수 파이썬으로 계산한다.
  • 의존성 = openpyxl + tksheet 뿐. pandas/bs4/numpy/matplotlib 등 추가 패키지 금지. 평균/중앙/백분위(P95)는 statistics 또는 수동 계산.
  • 오프라인. 결과 .html은 외부 CDN·스크립트 금지, CSS·그래프(SVG)를 파일 하나에 인라인. 런타임 인터넷 호출 금지.
  • 원본 read-only. Report 폴더의 .htm는 읽기만(수정·삭제·이동 금지).
  • 산출물은 전부 로컬(localdirs = 프로그램 옆 CamtekAOI/, OneDrive 저장폴더 금지). 취합 텍스트·엑셀·.html·누적 store·상태파일·캐시 모두 로컬.
  • 로컬 HTTP 서버 금지. 리스닝 소켓은 사내 EDR/Defender 오탐 위험(측면 이동·트로이로 오인 → 실행파일 삭제 실사고 이력). 실시간 창은 파일 재생성 + 브라우저 새로고침으로 구현(9장).
  • 지정 브랜치에서만 작업(claude/ux-bento-navy-lime 위에 이어서), 요청 없이 다른 브랜치 push·PR 금지.
  • GUI(tkinter/tksheet)·Excel·브라우저는 개발환경 미지원 → python3 -m py_compile + 헤드리스 테스트로 검증, 실기는 Windows 필요.

3. 입력 데이터 구조 (batch report)

3-1. 원본 *_BatchReport.htm

HTML 1개 = 배치 1회. 내부 <table> 3개.

  • 표1 Batch Info: 날짜.
  • 표2 요약(키-값 2열): Batch Start·Batch End·Batch Time·Wafers Scanned·Avg. Scan Time·Scanned Dice·Good Dice·Bad Dice·Yield·Job/Setup·User.
  • 표3 wafer 목록(순서=스캔 순): No | Lot | Wafer ID | Faults | Scanned Dice | Bad Dice | Good Dice | Yield | Pass/Fail | Recipe(s).

3-2. 합본 txt *_BatchReports_Combined.txt

[REPORT n/N]로 배치 구분, SOURCE_FILE: 뒤 원본명, [BATCH_INFO]·[WAFER_RESULTS] 블록, wafer는 탭(\t) 구분, WAFER_ROW_COUNT로 종료.

3-3. 파일명 내장 날짜(증분 수집의 핵심)

파일 이름에 _YY-Mon-DD_(HH.MM.SS)_(예 _26-Aug-30_(21.41.39)_)가 들어 있다. 파일을 열지 않고 이름만으로 날짜를 얻어 “마지막 조사 이후”만 고를 때 쓴다(빠름·원본 무접근). 파서: 기존 wph.parse_filename_datetime.

3-4. 핵심 필드 의미

필드위치쓰임
Batch Start / End요약배치 시작·종료(%d-%b-%y %I:%M:%S %p). 조치시간·가동률·시간축.
Batch Time요약스캔 소요시간(HH:MM:SS). WPH·가동률.
Wafers Scanned요약스캔 완료 wafer 수. WPH·완주율 분자.
Job/Setup요약자재·조건 식별자. Job(=recipe, / 앞)·조치시간 그룹 키.

6. 통합 지표 카탈로그 (지표 선택창 = 이 목록)

사용자 지시대로 “그룹 A/B”로 나누지 않고 지표별 단일 목록으로 둔다. 기존 WPH와 겹치는 항목은 새 정의 기준으로 통합(중복 제거). 각 지표는 선택창에서 개별 on/off, 기본 전부 on.

#지표계산목적 / 통합 메모
1유지 처리량 WPHActual WPH = Wafers×3600÷Batch sec. 전체·호기별·recipe별 누적/평균.기존 WPH 조사 그대로. 유효 매수(기본 25) 필터 유지.
2신규 가동률(스캔)호기마다 × 기간별(일/주/월) Σ(Batch Time) ÷ 관측창. 유휴 gap 분포. (7장 상세)실시간 대시보드의 주 지표. batch report 한계상 “스캔 가동률” proxy. 기간 전환은 HTML 내 토글.
3통합 에러 유형별 빈도 (A)Pass/Fail을 표준 유형으로 묶어 유형별 wafer수·배치수.기존 “scan 상태 요약(정상/error/확인불가)”·“에러 3단”을 여기로 흡수. 정상/에러/확인불가는 이 지표의 상위 집계로 표현.
4신규 에러 성격 (B)유형 → 예방형(설정·환경) / 조치형(공정·자재 판단) 매핑.자동화 방식 결정: 예방형→사전검증, 조치형→Hold·반송.
5신규 Aborted 왜곡보정 (C) ★배치 내 순서대로 훑어 첫 에러=트리거, 이후 Aborted=연쇄로 분리.가장 중요. wafer 순서(No) 필요 — 파서가 순서 보존하므로 가능.
6신규 조치 소요시간 (D)같은 Job/Setup 배치를 시각순 정렬, (다음 배치 start − 에러 배치 end). 0~1440분만 유효. 구간분포.빈도×조치시간=총손실. 한계: 대기시간 섞임 → 유형 간 상대 비교용.
7신규 복구 baseline (F)D의 전체 대표값(평균/중앙) 1개.자동화 전후 비교 기준선.
8신규 Recipe별 defect 임계치 (E)정상(Pass) wafer만 Recipe별 Bad Dice 평균·중앙·P95·최대.자동 Hold 임계치 근거. Recipe마다 정상 수준 달라 임계치도 달라야 함.
9신규 Yield/Bad Dice 급변 (G)같은 Recipe 시각순, 정상 분포(E) 밖 급락/튐 배치 표시.에러 안 뜨는 품질 저하(Focus 미세 틀어짐 등) 감지.
10신규 배치 완주율 (H)Wafers Scanned ÷ wafer 행수. 완주/부분실패/완전실패 태깅.무인 운전 안정성 목표치.
11신규 미분류 자동 포착분류 사전 어디에도 안 맞는 Pass/Fail → Unclassified로 원문 보존·목록화.새 에러 누락 방지(10장). 담당자는 사전에 한 줄만 추가.

7. 가동률 지표 상세 (신규)

확정(사용자): 가동률은 장비(호기)마다 × 기간별로 본다. 기간 단위는 일 / 주(ISO) / 월로 끊어 보며, 이 전환은 결과 HTML 안에서 즉시 가능하다(9장 — 세 단위 집계를 모두 파일에 내장하고 JS 토글).

7-1. 정의 · 수식

  • 스캔 가동률(호기 m, 기간 p) = Σ(Batch Time 초) ÷ 관측창(초). 분자 = 그 기간에 호기 m이 실제 스캔한 시간의 합.
  • 관측창(분모) 기본 = 달력 기준: 일=24h, 주=7×24h, 월=그 달 일수×24h. (달력시간 대비 스캔 비율 → 호기·기간 간 비교가 쉽다.)
  • 보조값 = 가동시간 기준: 관측창을 그 기간 내 첫 Batch Start~마지막 Batch End로 잡은 값도 함께 표기(비가동 대기를 뺀 "돌 때의 밀도"). 두 값을 나란히 보여 준다.
  • 유휴시간 = 관측창 − Σ스캔시간. 배치 간 gap(다음 start − 이전 end) 분포 · 유휴 상위 gap 목록.

7-2. 기간 버킷(일/주/월) 계산

  • 각 배치를 Batch Start 기준으로 버킷에 귀속(자정·월말 걸치면 start가 속한 버킷).
  • 일 = 날짜별, 주 = ISO week(월~일), 월 = 달력 월. 호기 × 버킷마다 가동률·스캔시간·배치수·유휴를 계산.
  • 진행 중인 이번 주/이번 달은 부분 집계: 관측창을 (버킷 시작 ~ 마지막 데이터 시각)으로 잡고 "진행 중" 표시(달력 전체로 나눠 과소평가되지 않게).
  • 표시: 호기별 가동률 막대(선택 기간 단위) + 기간 추이(일/주/월 토글) + 유휴 상위 gap 표.

7-3. 한계(반드시 명시)

batch report에는 스캔한 시간만 기록된다. 대기·PM·전원off·비스캔 셋업은 구분 불가하므로 이 값은 "장비가 실제 스캔한 시간의 비율"인 스캔 가동률(proxy)이다. 진짜 설비 가동률(OEE)은 장비 Event Log 확보 후 고도화한다. 결과 화면·문서에 이 한계를 각주로 표기한다.

  • 키 = source_file(파일명). 이미 있으면 skip(중복 방지).
  • 용량이 커지면 호기·연월별 파일 분할. 원본 htm은 다시 안 읽는다(누적 store만으로 재계산).

지표 재계산 = 누적 store 전체 기준(신규+과거)  # 원본 재파싱 없음
주의: 파일명 날짜가 없는 리포트(예외)는 기간 필터에서 빠질 수 있으므로, source_file 집합 중복 체크를 2차 안전장치로 병행한다. 백업 폴더(Reports_260402 등)가 여러 개면 각 폴더를 순회하되 동일 source_file은 한 번만.

9. 가동률 실시간(준실시간) 상태 창 — 설계 + 가능성 검토

9-1. 결론: 가능(조건부). 진짜 실시간은 아니다.

  • 구현 = 자체 완결 대시보드 .html(데이터 인라인) 재생성 + 브라우저 자동 새로고침. 서버 없음.
  • 파일 상단에 <meta http-equiv="refresh" content="1800">(예 30분) → 열려 있는 탭이 주기적으로 파일을 다시 읽어 갱신된 데이터 표시. “마지막 업데이트: {시각}” 크게 표기.
  • 갱신 트리거: ① 앱 [지금 업데이트] 버튼 → 증분 수집 → 대시보드 재생성 → 브라우저로 열기/갱신. ② 하루 1회 자동(기존 watcher.should_run/트레이 after 루프 재사용, 무인이라 모달 금지).
"업데이트"와 "기간 전환"은 다르다(확정):
  • 데이터 갱신(새 배치 반영) = 프로그램에서만. 오프라인 HTML은 스스로 장비 폴더를 스캔·재계산할 수 없다(그러려면 서버 필요 → 보안상 금지). HTML 안의 버튼은 최대 "새로고침(F5, 파일 다시 읽기)"까지만 가능하고, 수집해서 업데이트는 못 한다.
  • 재다운로드 불필요. 대시보드는 항상 같은 로컬 경로에 덮어쓰기 재생성하므로, 열어둔 탭·바로가기가 그대로 최신을 가리킨다. 매번 새 파일을 내려받지 않는다.
  • 기간 전환(일/주/월)은 HTML 안에서 즉시 가능. 프로그램이 파일을 만들 때 일·주·월 집계를 모두 내장하고, 화면의 [일별]/[주간]/[월별] 버튼은 내장 데이터만 JS로 토글한다(재수집·서버 없이 오프라인 즉시 전환).

9-2. 로컬 HTTP 서버를 쓰지 않는 이유(중요)

리스닝 소켓을 여는 서명 없는 exe는 사내 EDR/Defender에 측면 이동·백도어로 오탐될 수 있다(과거 net.exe 관리공유 접속이 트로이로 오탐돼 실행파일이 삭제된 실사고 있음). 따라서 서버·소켓 금지. 파일 재생성+meta refresh만으로 요구(하루 1회/버튼 갱신)를 충족한다.

9-3. 대시보드 구성(제안)

  • 상단: [일별]/[주간]/[월별] 토글 · 마지막 업데이트 시각 · 대상 호기 수 · 데이터 기간 · "갱신은 프로그램 [지금 업데이트]에서" 안내.
  • KPI: 전체 스캔 가동률 · 최근 24h 배치 수 · 이슈 배치 수 · 평균 WPH.
  • 호기별 가동률 막대(SVG) — 선택 기간 단위 · 호기별 기간 추이(SVG) — 일/주/월 토글에 따라 갱신 · 유휴 상위 gap 표 · 최근 에러 유형 top.
  • 데이터는 {호기: {일:[...], 주:[...], 월:[...]}} 형태로 세 단위 모두 내장(JS 토글이 이걸 골라 그림).
  • 오프라인 단일 파일, @media print 포함.
