# 불러오기 기능 대개편 — 통합 설계서 (Opus 4.8 인수인계용)

> 작성: Fable 5 (큰틀 설계). 이 문서는 **후속 세션(Opus 4.8 포함)이 맥락 없이 이어받아
> 구현할 수 있도록** 쓰였다. 작업 전 이 문서와 CLAUDE.md를 먼저 읽을 것.
> 작업 브랜치: `claude/program-load-feature-overhaul-bc4xbf`

## 0. 배경 / 목표

사용자가 터미널에서 쓰던 `recipe_param_extractor_network_v3.py`(이하 **extractor**)의
워크플로를 Para 프로그램(tkinter GUI) 안으로 통합한다.

extractor의 터미널 흐름:

```
장비 IP 입력 → net use \\IP\c$ 접속 → Job/Setup/Recipe 폴더 번호로 선택
→ GlobalRTP.ini + OpticPreset.ini + Zones/*.ini 를 로컬 staging에 복사(읽기전용)
→ initial(1차 검토용) 엑셀 생성 → 사용자가 엑셀을 직접 열어 행 삭제/추출여부 편집
→ 수정된 엑셀 경로를 다시 터미널에 입력 → final 엑셀 생성
→ (batch-update-final) 여러 IP 순회하며 final 양식 기준 값 재추출
```

이 전 과정을 프로그램 화면에서 진행하게 한다. 목표 5가지(사용자 원문 요약):

1. extractor 코드를 이용해 **파라미터 값 불러와서 업데이트** + **파라미터 양식 만들기** 구현
2. 엑셀 양식 통일 — extractor 양식이 아니라 **기존 공용 파일 양식(PI_ALL 스타일)** 을 따름
3. initial/final 파일은 **개별 폴더에 생성** — 공용 엑셀 파일과 같은 경로 아래
4. 터미널 입력 → 엑셀 수동 편집 → 경로 재입력의 과정을 **프로그램 화면에서** 진행
5. **값 갱신 전 공용 파일 백업** 자동 생성

## 1. 결정 사항 (사용자 확인 대기 항목 포함)

AskUserQuestion 전송이 실패해 아래 4개는 **권장 기본값으로 가정**하고 설계했다.
사용자가 다른 답을 주면 해당 절만 수정하면 되도록 모듈을 분리했다.
❗표시 = 사용자 확정 필요.

| # | 항목 | 가정(기본값) | 대안 |
|---|------|-------------|------|
| ❗1 | 네트워크 수집(net use `\\IP\c$`)을 GUI에 포함? | **포함** — 비밀번호는 메모리에만 보관, 읽기전용 복사. 단 Windows 전용 기능으로 분리(`collector.py`), 로컬 폴더 분석만으로도 전체 워크플로 동작 | 로컬 폴더만 / 별도 버튼 옵션 |
| ❗2 | 파싱 소스 | **둘 다 자동 판별** — 폴더에 `Zones/` 또는 `GlobalRTP.ini`가 있으면 extractor 방식(ini), `RTP.txt`가 있으면 기존 방식. 같은 레코드 스키마로 정규화 | .py 방식만 / RTP.txt만 |
| ❗3 | initial/final 폴더 구조 | **호기별/실행일시별**: `{공용파일폴더}/파라미터_수집/{AOI-호기}/{YYYYMMDD_HHMMSS}/` 아래 `staging/`, `01_초안(initial).xlsx`, `02_확정(final).xlsx`, `_수집로그.txt` | 실행별 단일 폴더 / 레시피레벨별 |
| ❗4 | 기존 메뉴(폴더 분석→취사선택 / 값 갱신) 처리 | **당분간 병행** — 새 통합 메뉴 "파라미터 불러오기(통합)…" 추가, 기존 메뉴는 유지. 안정화 후 제거 | 즉시 대체 |

이미 확정(CLAUDE.md, 재질문 금지): 스키마는 META_FIELDS 유지(PI=레시피레벨,
Recipe=변형), 변형 라벨 `PI`/`PI-bubble`(하이픈)/`x5`/`x20`, PI→`{stem}_PI.xlsx`(PI_ALL)
· RDL→`{stem}_RDL.xlsx`(RDL_ALL) 분리 저장, 원본 읽기전용, openpyxl+tksheet 외 의존성 금지.

## 2. 양식 통일 (세부목표 1)

extractor의 TEMPLATE_HEADERS/FINAL_HEADERS를 버리고, initial/final 모두
**기존 공용 파일과 같은 보이는 컬럼**을 쓴다:

```
PI | Recipe | Zone | Alg | Parameter | 초기 추천값 | 비고 | AOI-xx …
```

extractor 필드 → 기존 스키마 매핑:

| extractor | 기존 스키마 | 비고 |
|---|---|---|
| Job 폴더 키워드(PI3, RDL4…) | `PI` (레시피 레벨) | `auto_detect_job_keyword()` 이식 |
| Recipe 폴더명(PI/PI_BUBBLE/x5/x20) | `Recipe` (변형) | 라벨 정규화: `PI-bubble`, `x5`, `x20` |
| 상위항목 (ZoneName / Global / OpticPreset) | `Zone` | Global→`GlobalRTP`, OpticPreset→`LIGHT` 유지 검토 |
| 설정 Section | `Alg` | Surface/Genesis/필터류… |
| 표시 Parameter (KNOWN_DISPLAY_MAP 적용) | `Parameter` | rtp_template.json 추천이름과 병용 |
| 변환값(SCALE 0.8452 등) | 호기 열 값 | 변환방식은 매핑시트에 보존 |
| 장비(IP↔AOI) | `AOI-xx` 열 | 참고자료 시트의 IP표로 역매핑 |

**매칭·재추출용 메타데이터**(설정파일/설정 Section/설정 Parameter/Raw Value/변환방식/
Status/Source Path)는 보이는 시트를 어지럽히지 않도록 **숨김 시트 `_EXTRACT_MAP`**
(Row_ID 키)로 보존한다. 이 시트 덕분에 final 파일만 있으면 값 재추출(업데이트)이 가능하다.
기존 프로그램이 이 파일을 열어도 PI_ALL 시트만 읽으므로 호환된다.

- **initial(01_초안)** = 파싱 전체 + `추출여부` 개념 대신 프로그램 화면의 체크 상태를 반영해
  저장(감사/오프라인 검토용 스냅샷). 시트: PI_ALL 또는 RDL_ALL + `_EXTRACT_MAP` + `요약`.
- **final(02_확정)** = 화면에서 선택 확정된 행만. 같은 구조. MISSING 행은 빨간 배경(스타일은
  engine의 기존 스타일 함수 재사용).

## 3. 폴더/파일 배치 (세부목표 2)

공용 파일이 `D:\OneDrive\공용\TB500_PI.xlsx`라면:

```
D:\OneDrive\공용\
├─ TB500_PI.xlsx                      ← 공용 파일(그대로)
├─ 백업\
│   └─ TB500_PI_20260706_143000.xlsx  ← 값 갱신 직전 자동 백업(세부목표 5)
└─ 파라미터_수집\
    └─ AOI-13\
        └─ 20260706_1430\
            ├─ staging\PI3\GlobalRTP.ini, OpticPreset.ini, Zones….ini (또는 RTP.txt)
            ├─ 01_초안_AOI-13_PI3.xlsx
            ├─ 02_확정_AOI-13_PI3.xlsx
            └─ _수집로그.txt           ← extractor의 _collect_log.txt 형식 계승
```

- 경로 상수/생성 로직은 한 곳(`workdirs.py` 신설, 함수 3개: `backup_dir()`,
  `collect_dir(aoi)`, `new_run_dir(aoi)`)에 몰아 ❗3 변경 시 여기만 고치면 되게 한다.
- 백업 정책: `값 갱신` 실행마다 1회, 파일명 `{원본stem}_{YYYYMMDD_HHMMSS}.xlsx`.
  단순 복사(shutil.copy2). 보존 개수 제한은 두지 않음(사용자 OneDrive 관리).

## 4. GUI 워크플로 (세부목표 3) — 새 다이얼로그 "파라미터 불러오기(통합)"

기존 `_curate_dialog`(취사선택)를 확장한 **3단계 마법사** 하나로 통합한다.
파일 메뉴에 "파라미터 불러오기(통합)…" 추가.

### 1단계 — 수집(소스 선택)
- 라디오: `장비 네트워크(\\IP\c$)` / `로컬 폴더(이미 받아둔 것)`
- 네트워크 모드(❗1): IP 여러 개 입력(쉼표/줄바꿈), 접속 ID(기본 amkor), 비밀번호(getpass
  대신 `show="*"` Entry, 저장 안 함), 참고자료 시트의 IP표로 AOI 이름 자동 표시.
  Job/Setup/Recipe 선택은 extractor의 번호 입력 대신 **트리/리스트 위젯**으로.
  첫 장비에서 고른 선택을 plan(키워드 매칭)으로 다음 장비에 자동 적용 — extractor의
  `collect_recipe_files_from_equipment_planned()` 로직 이식.
- 수집 실행 → 호기별 run 폴더에 staging 복사(읽기전용, 로그 기록) → 자동으로 2단계.
- 로컬 모드: 폴더 선택 → 파싱만 하고 staging 복사 생략(또는 run 폴더로 복사 선택).

### 2단계 — 취사선택 (initial 역할, 엑셀 수동 편집 대체)
- 기존 취사선택 UI 유지·확장: 위=기존 양식 항목(기본 체크), 아래=신규 항목(기본 해제),
  섹션별 전체선택/해제, Recipe·배율 그룹 콤보, 추천이름/비고 인라인 수정.
- 추가: `01_초안` 자동 저장 버튼/체크(기본 켬) — 현재 체크 상태 그대로 스냅샷.
- extractor에서 "필수 셀 공란/추출여부 N" 제외 규칙은 화면 체크박스가 대신한다.

### 3단계 — 결과 생성 (final 역할) : 두 갈래 버튼
- **양식 만들기**: 선택 항목 → `engine.create_from_records()` (PI/RDL 분리 저장, 기존 로직
  그대로) + 같은 내용을 run 폴더에 `02_확정` 사본 저장 + `_EXTRACT_MAP` 시트 기록.
- **열린 공용 파일 값 갱신**: ①백업 생성 → ②매칭 키
  `(PI, Recipe(변형), norm_key(Zone), norm_key(Alg), norm_key(Parameter))` 로 해당 호기
  열만 갱신(기존 `rtp_parser.refresh_values()` 방식 계승, ini 소스 지원 추가)
  → ③변경 전/후 미리보기 표(바뀌는 셀 수, MISSING 목록) 확인 후 적용
  → ④`02_확정`을 run 폴더에 저장, 변경이력은 기존 save() 병합 로직이 기록.

## 5. 모듈 구조 / 작업 목록 (체크리스트 — 진행하며 갱신할 것)

의존성 추가 금지(openpyxl+tksheet). 네트워크 접속은 `net use` subprocess(Windows 전용,
비-Windows에서는 메뉴 비활성화 + 로컬 모드만).

- [ ] **T1. `param_manager/ini_parser.py` 신설** — extractor 파싱부 이식:
      `parse_ini_file`, `infer_top_item`, `KNOWN_DISPLAY_MAP`, `transform_value`(SCALE),
      `parse_raw_value`. 출력은 rtp_parser의 `RtpRow`와 동일 스키마로 정규화
      (`zone=상위항목, alg=섹션, param_raw=키, value=변환 전 raw`). 단위/변환방식 필드 추가.
- [ ] **T2. `rtp_parser.scan_tree` 확장(❗2)** — config 폴더 판별을
      `RTP.txt 존재` or `GlobalRTP.ini/Zones 존재`로 넓히고, 후자는 T1 파서로 파싱.
      `detect_meta`는 Job 키워드(PI3/RDL4)·Recipe 폴더명(x5/x20/PI/PI_BUBBLE)도 인식하게 보강.
- [ ] **T3. `param_manager/collector.py` 신설(❗1)** — extractor 수집부 이식:
      `connect/disconnect_admin_share(_password)`, `list_dirs`, `find_setup_candidates`,
      `resolve_setup_by_name`, `auto_detect_job_keyword`, plan 기반 자동 선택,
      계획 목록 반환(복사 전 확인용) + 읽기전용 복사 + 로그. **원본 무변경 원칙 주석 유지.**
      GUI 콜백(선택 요청)을 함수 인자로 받아 tkinter와 분리(테스트 가능하게).
- [ ] **T4. `param_manager/workdirs.py` 신설(❗3)** — 3절 경로 함수 + 백업 함수

- [ ] **T5. initial/final 기록기** — `engine.py`에
      `write_extract_workbook(dest, records, aoi, kind, extract_map, stage)` 추가:

- [ ] **T6. 값 갱신 엔진 확장** — `rtp_parser.refresh_values()`가 T2 확장 스캔 결과를 쓰도록,

- [ ] **T7. `equip_app.py` — 통합 마법사 다이얼로그** (4절). 기존 `_curate_dialog` 재사용

      `_EXTRACT_MAP` 왕복 테스트 추가. collector는 파일시스템 픽스처로 plan 매칭만 테스트
      (net use는 테스트 제외).
- [ ] **T9. 문서** — `docs/사용설명.md`에 새 워크플로 추가, CLAUDE.md 확정사항 갱신,

## 6. 매칭 키 / 값 갱신 규칙 (요약)

- 행 매칭: `(PI, Recipe, norm_key(Zone), norm_key(Alg), norm_key(Parameter))`
  — 기존 `refresh_values()`와 동일. `_EXTRACT_MAP`이 있으면
  `(설정파일, 설정 Section, 설정 Parameter)` 우선 매칭(더 정확), 없으면 이름 매칭 폴백.
- 값 비교는 문자열 정규화(`engine._s`) 기준. 빈 값은 덮어쓰지 않음(기존 정책 유지).
- 새 호기 등장 시 열 추가(기존 정책). 매칭 실패 행은 건드리지 않고 MISSING 목록으로 보고.
- 변환값 정책: 공용 파일에는 **화면 표시값(변환 후)** 을 기록, raw와 변환방식은
  `_EXTRACT_MAP`에 보존.

## 7. 제약 재확인

- conda 금지 / 런타임 외부(인터넷) 네트워크 금지 — 사내 장비망 `\\IP\c$` 접속은 사용자
  도구(extractor)가 이미 하던 것을 GUI로 옮기는 것이며 ❗1 확정 대상.
- 장비 원본은 **읽기/복사만**. 쓰기·삭제·이름변경 절대 금지. 복사 간 지연(0.1s) 유지.
- 비밀번호는 메모리만, 로그/설정파일에 기록 금지.
- openpyxl + tksheet 외 패키지 금지. tkinter 표준만.
