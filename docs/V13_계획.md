# V13 계획 — git clone 설치 · 업데이트, 자체 exe 없음, tkinter 제거 (검토용 초안)

- 작성 2026-11-10 · 기준 커밋 `version_v12` `4d3ee1f` · 상태: **소유자 검토 대기(구현 전)**
- 요청(소유자 세션): "V13 버전으로 다시 만들고 브랜치도 따로 생성해. 프로그램 업데이트 방식을 git clone 해서 업데이트하는 방식으로 전면 수정해. 예전 tkinter 관련된 거는 새로운 브랜치에서 없애. 계획부터 세워서 검토 맡아."

## 1. 왜 바꾸나 (지금까지 확인한 사실)

- v12.9.30 ~ 33 zip 이 회사 PC 에서 Defender(`Wacatac!ml`)에 막힌다. 관리자 권한이 없어 허용으로 바꿀 수 없고, OneDrive 로 옮겨도 막힌다.
- 같은 zip 을 최신 Defender 로 검사하면 '위협 없음'(window_defender 브랜치 실측). 막히는 이유는 **서명 없는 우리 exe(앱 exe · 엔진 exe)를 처음 보는 파일로 보는 평판 판정**이다.
- 반대로 GitHub 'Download ZIP'(소스 코드)은 받아진다. 실행 파일이 없기 때문이다.
- 결론: **우리가 만든 exe 를 배포하지 않으면** 이 문제가 사라진다. git clone 은 소스만 받으므로 이 방향과 맞다.

## 2. 핵심 설계 (제안)

git clone 으로 받은 것은 소스뿐이므로 "소스에서 바로 실행"이 되어야 한다. 빌드(Rust · Node · PyInstaller)는 사용자 PC 에서 하지 않는다.

| 부분 | v12 (지금) | v13 (제안) |
|---|---|---|
| 화면 | Tauri 앱 exe(우리가 빌드, 서명 없음) | **Edge 앱 창**(`msedge --app=http://127.0.0.1:포트`) — 회사 PC 에 이미 있는 서명된 Edge. 주소창 없는 별도 창 |
| 화면 코드 | exe 안에 내장 | 빌드된 React 결과(`frontend/dist`)를 **저장소에 커밋**(HTML · JS 글 파일) |
| 엔진 | PyInstaller exe(서명 없음) | **python.org 의 Python(PSF 서명)** 으로 `.py` 소스를 그대로 실행 |
| 화면 ↔ 엔진 | Tauri IPC(stdio) | **127.0.0.1 전용 로컬 HTTP + WebSocket**(외부 접속 불가, 실행할 때마다 바뀌는 접속 토큰) |
| 실행 | exe 더블클릭 | `Camtek_AOI_manager.pyw` 더블클릭(콘솔 창 없음) → 엔진 시작 + Edge 앱 창 열기 |
| 의존 패키지 | 빌드 때 포함 | `openpyxl`(순수 Python, MIT)을 **저장소에 넣음**(vendor) → 사용자 PC 에서 pip 불필요. tksheet 는 tkinter 와 함께 삭제 |
| 업데이트 | OneDrive 에 zip 게시 → 앱이 받아 엔진 exe 로 교체 | **[업데이트] 버튼 = `git fetch` + 최신 릴리스 태그로 `git checkout`**(아래 4절) |
| 릴리스 | GitHub Actions 가 Windows 빌드 → zip | **태그만**(`v13.x.y`) + 릴리스 노트. 빌드 산출물 없음 |

- 사용자 PC 에 필요한 것: **Python 3.11+**(python.org, '이 사용자만' 설치는 관리자 권한 불필요) · **Git for Windows**(사용자 폴더 설치 또는 PortableGit, 관리자 권한 불필요) · Edge(이미 있음).
- 우리 exe · dll · .bat · .ps1 이 하나도 없다. 실행 파일은 전부 서명된 Python · Git · Edge 것이다.

## 4. 업데이트 방식 (2026-11-10 소유자 확정: GitHub 업데이트가 메인, 이때만 인터넷 예외 — 아래 4-1 이 우선)

- **설치(최초 1회, 안내 문서)**: `git clone --branch v13.0.0 https://github.com/kimminkuy70-coder/Para.git %LOCALAPPDATA%\CamtekAOI\app` → 바탕화면 바로가기(`.pyw`).
  설치 폴더는 OneDrive 밖 로컬(종전 OneDrive 사고 원칙 유지). 사용자 설정 · 캐시는 지금처럼 `CamtekAOI\` 의 다른 폴더라 업데이트와 무관.
- **업데이트 대상 = 릴리스 태그만**: 앱이 `git fetch --tags` 뒤 가장 큰 `v13.*.*` 태그로 이동한다. 브랜치 끝(작업 중 커밋)은 사용자에게 가지 않는다.
- **흐름**: 시작할 때 조용히 확인(실패해도 무시) → 새 태그가 있으면 화면 위 안내 → 사람이 [업데이트] → 작업 중이 아니면 `git checkout` → 엔진 재시작 · 창 새로고침.
  실패하면 이전 태그로 그대로 둔다(git 이 원자적으로 바꿈). 설치 폴더에 사용자가 고친 파일이 있으면 업데이트를 멈추고 알린다(`--force` 안 씀).
- 회사망: Windows 인증서 저장소를 쓰도록 `http.sslBackend=schannel`(회사 TLS 검사 대응), 프록시는 시스템 설정. 저장소가 공개라 **토큰 · 계정 없음**.
- **원칙 변경(소유자 확정 2026-11-10)**: CLAUDE.md 의 "런타임 인터넷 금지 · 업데이트는 OneDrive 만" 결정을 v13 에서 **"github.com 의 이 저장소에서 git 으로 받는 것만 예외"** 로 바꾼다.
  그 밖의 인터넷 접근 · 자동 다운로드 실행은 계속 금지.

### 4-1. 확정안 (2026-11-10 소유자: "업데이트는 github 업데이트가 메인으로, 이때만 인터넷 다운로드 가능하게끔 원칙 예외로 수정해")

- **메인 통로 = GitHub**: 앱이 `github.com/kimminkuy70-coder/Para` 에서 가장 큰 `v13.*.*` 릴리스 태그를 확인하고, **태그 zip**(`archive/refs/tags/v13.x.y.zip`, 소스만 · exe 없음)을 받는다.
  사용자 PC 에 Git 은 필요 없다(urllib). 받은 zip → 로컬 Temp → 풀기 · 검증 → `app.new` → 다음 실행 때 실행기가 교체, 실패하면 이전 판 그대로.
- **인터넷 예외 범위(이 밖은 계속 금지)**: ① 대상 = github.com / api.github.com / codeload.github.com 의 **이 저장소 하나** ② 용도 = 새 판 확인 + 소스 zip 받기 뿐
  ③ TLS 검증 필수(Windows 인증서 저장소 사용, 검증 끄기 · 재시도 금지) ④ 토큰 · 계정 없음(공개 저장소) ⑤ 받은 것 중 실행 파일(exe · dll · bat · ps1 · vbs)이 있으면 적용 거부
  ⑥ 확인은 시작할 때 조용히 1번(실패 무시), 받기 · 적용은 **사람이 [업데이트] 를 누를 때만** ⑦ 텔레메트리 · 다른 사이트 접속 · 자동 실행 다운로드 없음.
- **보조 통로 = OneDrive**: github.com 이 회사망에서 막힐 때를 대비해 같은 소스 zip 을 `프로그램/` 에 게시할 수 있게 둔다(종전 원칙: 로컬 Temp 복사 · SHA-256 확인).
- **저장소 공개 유지**: 토큰 없이 받으려면 공개여야 한다(2026-11-10 확인: 공개). 비공개로 바꾸면 PC 마다 토큰을 저장해야 해 자격 증명 원칙 위반 → 그때는 배포 파일만 담은 별도 공개 저장소로.
  공개이므로 회사 데이터 · 비밀 값을 저장소에 넣지 않는 규칙을 계속 지킨다.
- v13 브랜치의 CLAUDE.md · `IT보안_검토자료.md` · `보안_라이선스_검토.md` 에 이 예외를 적는다(인터넷 접근: "없음" → "github.com 이 저장소, 업데이트 때만").

- Windows 실기(고르기 창 · 트레이 · Edge 창 · 회사망 git)는 이 환경에서 확인할 수 없다.

- 막히지 않는 이유(추정): 디스크에 있는 실행 파일이 **많은 PC 에 이미 있는 것**(Python · Qt · numpy 등)뿐이고, 업데이트로 받는 것은 `.py` 글 파일뿐이다. 우리처럼 **이 프로그램만 쓰는 새 exe**(Tauri 앱 · PyInstaller 엔진)가 없다. Para v12 의 막힘 원인 판단(평판 판정)과 맞는다.
- `.bat`(`run_aoi.bat` · `update_app.bat`)이 있어도 막히지 않았다. 다만 Para 는 #31 에서 `.bat` 문구로 `Trojan:Script` 판정을 받은 적이 있으므로 V13 은 `.pyw` 바로가기로 bat 없이 간다(지금 안 유지).
- **V13 에 가져올 만한 것(소유자 선택 필요)**:
  - 안 B — **Git 설치 없이**: Git 대신 그 프로그램처럼 GitHub 의 **태그 zip**(`archive/refs/tags/v13.x.y.zip`)을 urllib 로 받아 `app.new` 로 준비 → 다음 실행 때 교체. 사용자 PC 에 필요한 것 = Python 만.
  - 안 C — **Python 도 같이 넣기**: python.org 의 embeddable zip(PSF 서명 exe)을 첫 설치 묶음에 넣으면 Python 설치도 필요 없다. 이 경우 첫 설치 zip 에 python.exe 가 들어가지만, 우리 exe 가 아니라 흔한 파일이라 평판 판정에 걸릴 가능성이 낮다(확인 전).
  - 업데이트 확인 실패는 조용히 무시, 준비가 끝난 것만 적용(rename 신호), 실패하면 이전 판 유지 — V13 4절에 그대로 반영.

### 10-1. Python 이 없는 PC (2026-11-10 소유자 질문 "파이썬이 없어도 되나?")

- 그 프로그램의 처리 방법 3가지(`bootstrap.py` · `run_aoi.bat` 확인):
  ① 전체 묶음 = `python\`(python-build-standalone 3.11) + 패키지까지 넣어 배포 ② lite = Python 만 넣고 첫 실행 때 pip 로 패키지 설치(`.deps_installed` 표식)
  ③ 온라인 = 작은 PyInstaller exe 가 GitHub 에서 Python(tar.gz) · 앱 zip 을 받고 pip 설치. ③ 은 **우리가 만든 exe** 라 Para 에서는 막힐 위험이 크다.
- Para V13 은 더 간단하다: 외부 패키지가 **openpyxl 하나(순수 Python)** 라 저장소에 넣으면 **pip · PyPI 접속이 필요 없다**. tkinter 를 지우므로 embeddable Python 에 tkinter 가 없어도 된다(ctypes 는 있음).
- 제안(안 C 구체화): **첫 설치 zip = python.org Windows embeddable(약 10MB, PSF 서명) + 소스**. 사용자는 아무것도 설치하지 않는다. 업데이트는 소스 zip(태그)만 받는다(Python 은 그대로). Python 판을 올릴 때만 새 설치 zip.
- 확인 전: 그 첫 설치 zip 이 회사 Defender 를 통과하는지 → 구현 첫 단계에서 시험 zip 을 만들어 소유자가 받아 보는 것으로 확인. 막히면 python.org 설치('이 사용자만')로 물러난다.

### 11-2. 저촉되는 곳과 고칠 방법

① **설치 폴더가 OneDrive 안이 되면 사고 ③ 재발.** 회사 PC 는 바탕화면 · 문서가 OneDrive 로 연결된 경우가 많다. 첫 설치 zip 을 거기에 풀면
  Python(파일 수백 개) + 소스(약 1천 개) + 업데이트마다 `app.new` 전체가 동기화된다.
  → 실행기가 시작할 때 자기 위치가 OneDrive 안이면(`localdirs.is_under_onedrive`) **실행을 멈추고** `%LOCALAPPDATA%\CamtekAOI\app` 으로 옮기라고 안내. 업데이트 준비 · 교체도 로컬 안에서만.
② **`__pycache__` 쓰기.** Python 은 소스 옆에 `.pyc` 를 만든다(설치 폴더가 OneDrive 면 ①과 같은 문제, 로컬이어도 업데이트마다 새로 생김).
  → `sys.dont_write_bytecode = True`(또는 pycache 를 `CamtekAOI\Cache` 로 `PYTHONPYCACHEPREFIX`). 성능 차이는 작음.
③ **로컬 HTTP 서버(포트 열기)** — 종전 검토 문서는 "포트 개방 없음"이었다. EDR 이 듣는 소켓을 볼 수 있다.
  → `127.0.0.1` 에만 묶는다(0.0.0.0 금지 — Windows 방화벽 창도 안 뜸). 실행마다 바뀌는 토큰 · Origin 검사, 다른 PC 접속 불가. `IT보안_검토자료.md` 에 명시.
④ **Edge 를 실행하는 방법.** `--remote-debugging-port` 는 쿠키 탈취 악성 코드가 쓰는 방식이라 EDR 탐지 대상 → **쓰지 않는다**.
  `msedge --app=http://127.0.0.1:포트/?t=토큰` 과 로컬 `--user-data-dir`(CamtekAOI 아래)만.
⑤ **이제 모든 소스가 디스크에 글 파일로 놓인다.** #58 규칙(엔진에서 닿는 모듈에 bat 문구 금지)이 **배포되는 파일 전체**로 넓어진다.
  저장소에는 아직 `build.bat` · `build_exe.bat` · `run_dev.bat` · `run_silent.bat` · `run_web_dev.bat` 이 있고, 문서 · 시험에 bat 문구가 많다.
  → (가) .bat 5개 삭제 (나) **배포 zip 에는 실행에 필요한 것만**(`param_manager/` · `frontend/dist/` · 실행기 · vendor) — `tests/` `tools/` `docs/` `.github/` 제외
  (나) 를 `tests/test_sidecar_no_scripts.py` 처럼 배포 목록 전체를 검사하는 시험으로 고정.
⑥ **실행 방법에 bat 을 쓰지 않는다.** embeddable Python 은 `.pyw` 연결이 없어 `.pyw` 더블클릭이 안 된다.
  → 첫 설치 zip 에 **바로가기(.lnk)** 를 넣는다: 대상 = `%LOCALAPPDATA%\CamtekAOI\app\python\pythonw.exe`, 인자 = 실행기(.lnk 는 환경 변수 경로 가능).
  설치 = "zip 을 `%LOCALAPPDATA%\CamtekAOI\app` 에 풀기" 고정 경로. 바탕화면 바로가기는 앱이 처음 실행될 때 만든다(그 프로그램의 `shortcut.py` 와 같은 방식, 스크립트 없음).
  업데이트 교체(`app.new` → `app`)도 bat 이 아니라 **Python 실행기 자신**이 앱을 띄우기 전에 한다.
⑦ **업데이트 경로** — ~~OneDrive 를 기본으로 하자는 제안~~은 소유자가 기각(2026-11-10, GitHub 메인 · 인터넷 예외 확정 → 4-1). 아래는 당시 검토 기록. 4절의 git/GitHub 방식은 원칙 ⑤ 를 깨야 하고, 회사 프록시가 github.com 을 막을 수도 있다.
  막힌 원인은 'OneDrive 통로'가 아니라 'zip 안의 우리 exe' 였다. 그러므로 **종전처럼 OneDrive `프로그램/` 폴더에 게시하되 내용을 소스 zip(.py · .js · .html, exe 없음)으로** 바꾸면
  인터넷 접속 없이 원칙을 그대로 지킨다. 받는 쪽은 종전 원칙대로 로컬 Temp 로 복사 → 크기 · SHA-256 확인 → `app.new` 로 풀기 → 다음 실행 때 교체.
  GitHub 다운로드는 (소유자가 원칙 변경에 동의할 때만) 보조 경로로: 버튼을 누를 때만, `github.com/kimminkuy70-coder/Para` 태그 zip 하나만, TLS 검증 끄기 금지, 토큰 없음(공개 저장소).
  → 이렇게 하면 **사용자 PC 에 Git 이 필요 없다**(4절의 git clone · checkout 은 개발자용으로만).
